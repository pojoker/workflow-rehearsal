# 光模块供应链研究：从这里开始

这个项目做了两件事：

1. 用公开披露重建光模块产业中“谁向谁供货”的可验证骨架；
2. 把这次研究过程沉淀成一套可复跑的供应链研究流程。

它不是一张覆盖全行业的名单。公开文件只会露出部分关系，因此项目同时保留了
“已经证实的边”和“知道金额、但不知道对手方是谁的匿名槽位”。

## 如果你只想看研究结论

按这个顺序读：

1. [光模块产业结构-v1.5.md](output/光模块产业结构-v1.5.md)：当前版——分层产业结构（236边169节点，材料→芯片→封装→器件→模块→终端+DSP产品映射盲区）；v1.4 及更早为冻结快照；
2. [光模块产业图谱-v1.5.html](output/光模块产业图谱-v1.5.html)：当前版分层交互图谱（236边169节点）；v1.4 及更早为冻结快照；
3. [edges.csv](output/edges.csv)：人工复核台账，正文中的 E 编号都在这里；
4. [deanonymization-cases.md](output/deanonymization-cases.md)：查看匿名客户是怎样被判定的。

一句话结论：公开披露可以还原一条可信的产业骨架，但无法还原完整终端流向；最难穿透的
不是匿名名称，而是 PINEWAVE、浙江粮油、Digicomm 这类真实存在的平台、代理与分销夹层。

## 怎样判断一条关系能不能引用

| 标记 | 含义 | 使用方式 |
|---|---|---|
| 实边 | 文件直接点名交易双方，并披露年份与占比或金额 | 可以承重引用 |
| 推断边（A级） | 多份硬证据互相锁定，仍属于推断 | 可以引用，但必须写明“推断” |
| 半边 / 半边槽位 | 金额或占比已知，对手方仍匿名，或点名证据不足 | 只能说明集中度，不能猜名字 |
| 程序段落泄漏 | 在收入确认、关联交易等段落发现实名主体 | 先判断它是终端、平台还是代理 |
| 机器层 | 自动抽取、尚未逐条人工复核 | 只能用于筛查与监测，不能承重 |

当前台账为 **236 条边、169 个节点**（截至 2026-07-24，v1.6 结构补全+修复轮重装）。台账为**人工准入、部分机械抽取装配并经固定种子抽样复核**（v1.6 新增边非逐条纯人工誊录）；
自动抽取层为 **300 条边**。两者不要混用。各版本报告对应的台账快照与信息截止日见
[VERSION-STATE.md](VERSION-STATE.md)——**引用任何数字请先认版本**（v0.1/v1.0/v1.1
报告仍反映其冻结时的 71/81 边，非本数字）。

## 如果你关心自动抽取 Demo

`demo/` 是 A 股年报抽取管线，不是正式研究结论。它把 30 份年报抽取成 300 条机器边，
用于证明“下载 → 抽取 → 生成边 → 可视化”的流程能跑通。入口是
[demo/SPEC.md](demo/SPEC.md)，验收结果见 [demo/VERIFICATION.md](demo/VERIFICATION.md)。

## 版本关系

- `v0.1`：彩排结束时的完整研究底稿，信息密度高（冻结）；
- `v1.0`：在 v0.1 上追加扩量结果，更像版本增量说明（冻结）；
- `v1.1-易读版`：把两版合并重写为独立报告（冻结历史版，81边/42节点快照）；
- `v1.4`：**当前版**——99边/48节点快照，红队订正措辞，含时间维度与方法论实测章。

需要审计时以 `output/edges.csv` 为准；需要理解时先读 v1.4。
