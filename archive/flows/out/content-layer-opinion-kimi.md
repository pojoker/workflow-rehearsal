# 内容层提案评议 — kimi（线索池/图谱前端车道）

> **日期**：2026-07-24
> **原料**：`logs/anomalies.md` 末条（前提级发现）、`flows/out/content-layer-sample-lieqi.md`（34条样品）、`flows/discussion-content-layer.md`（待裁决五项）
> **独立性声明**：未读 codex 任何评审文件；未读不改他人发言内容
> **一句话立场**：**支持入正式流程**——但以"并列独立台账 + schema/词表先冻结 + ⑤类永不承重"为三个硬条件；前端用 v1.5 模板做双视图适配，关系图谱画布不动。

## ① 该不该入正式流程：该，三个硬条件

从本车道（线索池/图谱前端）看，内容层不是"让报告不空"的装饰品，它直接补两块现有体系自己承认的缺口：

- **图谱缺"意义轴"**。v1.5 画布回答"我们凭什么看得见这条关系"，但点进 猎奇→旭创 的抽屉，只有金额与引语，没有"这是耦合设备进耦合工序"。样品 ④ 类的台账缺口注记说的就是这个。关系台账给结构，内容层给含义，两者是互补资产不是竞争资产。
- **线索池多一路约束源**。④ 类的负空间（猎奇明确**不覆盖**引线键合）约束了边的含义空间——图谱上任何 猎奇→X 的边都不可能是键合设备边。② 类参数构成技术指纹：1.6T 量产需要 ±3µm 级贴装（C13），若某推断边的对手方最高机型只有 ±5µm，推断等级该降。内容层可以为解匿和解蔽服务，这是本车道支持它的最强理由，比"报告更空"的动机更硬。

**三个硬条件**：

1. **并列独立台账，独立准入纪律**。内容层条目永不反向升格关系边——样品诚实边界第 1 条已有此约定，入正式流程时须从样品注记升级为 SOP 条文。
2. **schema 与工序受控词表先冻结，再全量抽取**。理由见 ②，样品内部已存在三套工序表述，不收敛词表就放量等于批量制造同义漂移。
3. **⑤类永不承重写成 lint 级规则**，不是倡议。内容栏"发行人称"前缀、自述标记锁定、不得被其他条目的证据链引用——三条都可机器检查，就不需要靠自觉。

提案方"原料零采集成本、锚标准实测可执行"两点本车道复核属实：34/34 引语回源，锚纪律与边四件套同构，前端可直接复用抽屉组件承载，无新交互成本。

## ② 五类 schema 怎么改

五类的分类骨架成立（定义类①/参数类②/代际类③/映射类④/自述类⑤），样品阶段的问题在**字段粒度不够机器用**。逐条修改建议：

### 通用字段（全五类追加）

| 字段 | 理由 |
|---|---|
| `id = CL-{来源简称}-{序号}` | 样品 C01–C34 只在单文件内唯一，多源抽取必撞号 |
| `scope = issuer / industry` | ③类实为两亚类：C15/C16 是发行人产品演进自述（立场近⑤），C17–C20 是行业描述。加 scope 字段比拆第六类干净 |
| `锚类型` | 提案点名了 招股书技术章节/datasheet/标准文档/专利 四类锚，样品只跑通一类；锚类型必须成字段，否则"技术类锚标准"无从审计 |
| `原始性 = 原文 / 转载` | C13 弗若斯特沙利文表是**转载**。seed E015 转录失真判例（36.3% vs 36.79%）在前：转载条降锚级、禁作金额/参数指纹主证 |
| `陈述时点 as-of` | C19"800G 规模化交付/1.6T 测试/3.2T 预研"是会老化的行业描述。台账侧已为披露可见性事件拆 `first_observed/last_observed`，内容层从第一天就带 as-of，省一轮补债 |

### 类型特化

- **②技术参数 → 强制结构化**：`参数主体 / 参数名 / 数值 / 单位 / 适用代际` 五元组，复合条目拆行。C13 的"400G ±5µm；800G/1.6T ±3µm"应是两行不是一条——复合条无法被前端按代际过滤，也无法做参数指纹比对。
- **④设备-工序映射 → 按关系处理**：它不是事实条，是三元组 `(设备型号 → 工序 → 证据)`。工序字段**必须走受控词表**（样品内 C01 四步封测 / C06 中游四步 / C28 五步含封装三套表述并存，这就是词表必要性的实物证据）。追加 `关联边ID（可空）` + `挂接状态 = 候选 / 已核验`：④类条目可以挂在既有边上作为工序属性**候选**，但状态机与边准入纪律解耦，绝不静默升格。
- **⑤发行人竞争陈述 → schema 级围栏**：`自述=true` 字段锁定 + `承重=0` 约定 + "发行人称"前缀进 linter。份额/排名数字（C29–C31）在结构化字段里应标注`自述数字`，防止下游把它们当市场数据抽走。

### 工序受控词表 v0（先于全量抽取）

由 ①类条目收敛，样品已可出初版骨架：`芯片贴装(贴片) / 引线键合 / 光学耦合 / 封装成型 / 老化测试(测试验证)`，每条挂别名与来源条目。项目已有 `flows/BOM-词表-v0.md` 的词表先例，工序词表沿用同一模式即可，不另造格式。

## ③ 前端形态：v1.5 模板双视图适配

用户已定适配我的 v1.5 图谱模板。先声明 v1.5 的两条核心语法，内容层适配必须继承而不是绕开：

- **画布只放结构，证据全在抽屉**。画布上任何一个视觉元素都不承载未经抽屉四件套（引语+章节+锚点+立场）背书的信息。
- **一种视觉通道只编码一种含义**。v1.5 里线型=证据等级（五种已满）、颜色=国别、流动动画=实边、虚线描边=盲区。内容层想加新信息，只能开新视图或新组件，不能往已占用的通道上叠。

### 方案：单壳双视图

同一个 HTML 壳（`.wrap / .stage / .drawer / .stats / .legend` 全部复用），eyebrow 处加视图切换：`[关系图谱] [工序图谱]`。同一份设计系统、同一个抽屉组件、两份内嵌 JSON。

**View 1 关系图谱（v1.5 原样，仅两处增量）**：

1. **边抽屉加"工序属性"字段块**：列出该边挂接的 ④类条目（设备型号→工序，状态=候选/已核验），每条带自己的锚点引语。抽屉的 `field()` 组件直接扩展，无新交互。
2. **画布边中点 ◆ 微章**：有工序属性的边在中点加一个小菱形——已核验=实色青（沿用 `--lit`），候选=琥珀描边（沿用 `--infer` 色但不占用虚线线型）。每边 ≤3 枚，超出 `+n`。点击微章开抽屉并定位到工序属性块。
3. legend 加一枚 `含工序属性` 过滤 chip（高亮有 ◆ 的边）——**是过滤器不是第六种边类**，五类证据语法不动。
4. 无映射的边，抽屉显式写 `工序属性：无 — 披露未及`。负空间可见是 v1.5 的原则（盲区描边、阴影半边都是），工序属性同样适用。

**View 2 工序图谱（新视图，模板适配）**：

- **脊椎 = 工序受控词表的横向流程带**：`贴片 → 引线键合 → 光学耦合 → 封装成型 → 老化测试` 五个站台式节点横向排列，视觉上沿用 v1.5 的 band-label 风格连成流程脊。
- **顶部代际条**：`100G → 400G → 800G → 1.6T → 3.2T(预研)` 时间/速率轴横跨脊椎上方（数据来源③类）。各站台标注代际精度阶梯——贴片站挂 `±5µm@400G → ±3µm@800G+`（C13 拆行后的两行②类数据正好渲染成阶梯）。这是"为什么工序在收紧"的唯一视觉化答案，是内容层独有的增量信息。
- **站台下挂设备卡**（④+② 联合渲染）：型号 + 关键参数 + 厂商 + 适用代际，如 `HP-EB3300 · ±1µm · 猎奇 · ≤1.6T`。卡片颜色编码**锚等级**（原文/转载/自述），不用国别——国别通道属于 View 1。
- **引线键合站保持空站可见**：已知覆盖缺口（猎奇不覆盖、图谱暂无键合设备商）直接渲染为带虚线描边的空站台——把 v1.5 的盲区视觉语言复用到工序维度，空站本身就是线索池的下一类发现目标。
- **公司不作为节点出现**，只作设备卡上的厂商徽章。避免与 View 1 重复造第二张公司关系网。
- **点击任何站台/设备卡 → 抽屉**：命中引语 + 章节位置 + 锚点 URL + 立场标注，四件套原样承载。交互肌肉记忆与 View 1 完全一致。
- **⑤类永不上画布**。只在抽屉内以引用块呈现，专用边框色 + "发行人称"前缀，样式上一眼可辨为自述。份额数字不驱动任何几何（不做气泡大小、不做节点位置）。

**明确不做**：

- 不给工序脊椎加流动动画——动画在 v1.5 里已编码"实边"，复用会误导。
- 不在 View 1 加第六种线型/颜色编码工序——通道已满。
- 不做两种视图的联动高亮（本期）：先各自站稳，联动等 schema 冻结后作为二期。

**Stats 行**：View 2 复用 `.stats` 组件，改显 `N 工序站 / N 设备条目 / N 参数条 / N 自述条`。前端计数直接读数据，所以 schema 冻结时必须对账条目数——讨论版头写"32条五类"，样品汇总表是 34（6+8+6+8+6），这个不一致要先销掉；v1.5 红队已有 98 vs 99 的前科，计数类错误会直接上画布。

**实施前提**：内容层 CSV 契约（字段+词表+⑤围栏 lint）冻结之后再动工写 View 2，避免 schema 漂移返工——anomalies 里版本基线漂移的教训刚交过学费。

## ④ 全量抽取范围建议

按**对图谱的边际价值**排序，不按文档完备性排序：

| 优先级 | 范围 | 理由 |
|---|---|---|
| P0 | 已在语料的 5 份招股书「业务与技术」章节 | T1 签字担责、零采集成本；④类直接注释既有边（猎奇→旭创 等）；样品已实测 34条/份的产出率 |
| P1 | 在图 48 节点中年报的技术/产品段落（经营讨论、研发、主要产品） | 只抽技术段不抽全文；按节点度降序，同层已有招股书覆盖的跳过；目标=每个 L3 设备节点与 L5 模块节点 ≥1 内容源 |
| P2 | 工序词表缺口驱动的补源 | 词表冻结后缺口即清单（首例：引线键合设备商），作为新线索类进 discovery queue 排序 |
| 试点后定量 | datasheet / 标准文档 / 专利 | 锚成本与核验纪律不同于叙事章节，先各试 1 份跑通再放量；专利单条边际价值最低，排最后 |

**硬排除**：研报/新闻不作内容锚（与边纪律一致）；他述⑤（甲发行人招股书中关于乙公司的陈述）不收，保持立场单一。

**排序与停止规则**：抽取顺序由 discovery queue 按 `可注释既有边数 × 节点度` 排序；试点批 = 5 份招股书 + 高度数节点年报技术段，完成后评审再定全量。量级估算：5 份招股书 ≈ 150–200 条，年报技术段 10–20 条/司——手工 CSV 可维护，前端内嵌 JSON 无压力。
