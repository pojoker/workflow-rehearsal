# 分支 F（前瞻，预注册正式试验——v3 核心增量）

### F.1 T0 与信息集不存在性证明

**T0 = 2026-07-24**（本文件冻结日）。

**信息集**：T0 冻结时刻 `flows/out/customs-partners.csv` 库内全部数据，
覆盖 202501–202606（连续 18 个月）。

**关键论证——评估数据在协议冻结时物理上不存在**：

预测窗口为 2026-07～2026-12，评估该窗口需要海关 202607–202612 六个批次的
"HS编码×贸易伙伴"细分月度数据。按 v2 §3.1 证据层 B（已核实的收敛二手
印证，本轮不重新核验，直接复用该结论）：海关统计在线查询平台的细分数据
开放节奏为**次月20日前后**。据此，2026-07 批次数据最早约在 2026-08-20
前后才会上线，即本文件冻结当天（2026-07-24）**尚未发布**。

本轮直接核验本项目数据库现状，取得比"发布节奏推断"更强的一手证据：

```
$ grep -c "^2026" flows/out/customs-partners.csv          → 978 行（202601–202606）
$ grep -E "^20260[7-9]|^2026[1-9][0-9]" flows/out/customs-partners.csv → 0 行匹配
$ awk -F, 'NR>1{print $1}' flows/out/customs-partners.csv | sort -u | tail -1 → 202606
```

`customs-partners.csv` 文件本身不含任何 202607 及以后的行——这不是"预测者
在 T0 看不到"的主观信息屏蔽，而是"采集方也从未采集到、因为官方还没发布"
的客观数据缺位。这一点与分支 H 的历史窗口有本质区别：

- **v2 历史分支的揭盲问题**（codex 发现9）：数据早已存在于库中，只是
  "协议设计时是否看过"的认识论问题——不适用于分支 F，因为分支 F 的
  评估数据尚未产生，无论协议作者主观上想不想看，都物理上看不到。
- **T0 发布日一手证据问题**（codex 发现1）：该问题是"如何证明某个历史
  文件在 T0 之前已经披露"——不适用于分支 F，因为分支 F 的 T0 就是协议
  撰写的当下，信息集直接取"此刻数据库已有的数据"，不涉及回溯性披露日
  核验。

因此，分支 F 是本项目迄今唯一一个**真正满足"结果尚未产生"意义上盲态**的
回测实例。
