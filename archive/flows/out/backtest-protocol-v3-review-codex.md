## 结论

**需修改后重审。**

v3 的双分支重构方向正确。分支 H 已实质降格，发现1、发现6不在 H 中追溯
修复的理由可以接受；分支 F 也确实处在目标结果尚未产生的真盲态。固定终点不
换月、F2 改作基准、实际事件与增量价值分门判断，均修复了 v2 的主要结构问题。

但当前还不能通过，阻断项有三组：

1. F.1 声明信息集有18个月，F.3 却未经规则说明只取最近6个月，再以“6个月
   信息集的一半”论证3个月窗口无自由度；候选族并未真正冻结。我在正式比对前
   提出第五个无调参机械候选：全窗口中位数外推。
2. v3 当前仍是 git 未跟踪文件，`T0=冻结日`尚无不可变版本锚点；F.9.5 又允许
   在目标值逐月暴露后发布 v3a“澄清”，重新打开了事后解释空间。
3. 分支 H 仍有“验证计算管线本身没有 bug”的越权措辞；一次烟雾测试只能证明
   固定夹具走通，不能证明实现无 bug。

这些问题都可在任何2026-07评估值出现前修复，不构成“不通过”，但须形成 v3a、
重新复审并立即用 commit hash 冻结。

## 结果盲态声明

我确认：本次复审期间，我没有看到 2026-07～2026-12 任一月份的实际美国金额、
实际马来西亚金额、实际 Δ、误差或 MAE。v3 中第254～259行是**预测值**，不是
评估值；第211～216行是2026-01～06的历史输入，也不是目标窗口结果。

本地只读核验得到：

- `customs-partners.csv` 最大月份为 `202606`；
- `202607`～`202612` 行数为0；
- `backtest-protocol-v3-result.md` 不存在。

2026-07-24时7月尚未结束，因此完整2026-07月官方月度统计不可能已经形成。
海关官方发布日历还明确说明，各月发布的是“上月”数据，在线查询通常在发布月
20日开放；这与本地不存在性证据一致
（[GACC Release Calendar](https://english.customs.gov.cn/Statics/fc662cee-21c3-474e-a7fb-4768bb1e295a.html)，
检索日期2026-07-24）。

所以我接受 F 分支的**结果真盲**论证；但“结果尚未产生”不等于“协议已经冻结”，
后者仍须由不可变版本锚点闭合。
