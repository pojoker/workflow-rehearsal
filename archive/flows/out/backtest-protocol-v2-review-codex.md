# backtest-protocol-v2 盲审意见（Codex）

评审对象：`flows/out/backtest-protocol-v2.md`  
对照文件：`flows/out/backtest-protocol-v1.md`、`flows/out/roadmap-review-codex.md`  
评审日期：2026-07-24  
评审边界：未读取底层 `customs-partners.csv`，未计算任何评估窗口实际 Δ、误差或
MAE，亦不判断回测将通过还是失败。

## 结论

**需修改后重审。**

v2 对“无图谱信号”、F2 与线性基准重合、历史回测不是真未来样本等限制披露得
较充分；`ceil(2n/3)` 也可追溯到 v1 的 4/6，80% 同样不是 v2 临时新增。但当前
仍有五个阻断项：

1. T0 所依赖的细分数据开放日没有一手证据闭合；
2. F1 的三个月窗口没有候选集合或选择规则，无法排除公式选择自由度；
3. 缺失值规则在看见具体缺失月和评估值后新增，且把固定终点改成最晚可用月；
4. “预测方向自洽”与“实际方向命中”拆开后，步骤4并未实现其声称的实际方向
   检查；
5. 正文已经生成预测向量、执行数据完整性检查并列出评估窗口实际输入，三处
   “未运行”声明因此不够准确，且评审材料已发生实质揭盲。

这些问题在不计算实际 Δ/MAE 的情况下即可判断。v3 修复后仍可作为回测工作流
彩排；本历史窗口不能据此升级为结果盲的样本外验证。

## 逐条发现

### 发现 1

**发现={条款位置：§3.1，第192–249行；§3.4，第265–281行；问题：T0 的一天边际
本身未显示方向偏置，但细分口径的可用日尚未闭合；严重度：高；建议：取得一手
发布时间表或可审计的平台时间戳后再冻结 T0，在此之前不得进入实际比对。}**

- 从 2025-06-20 改为 2025-06-21，并没有改变本协议纳入的历史月份
  （仍为2025-01～05）或评估月份，因此这“一天”不会改变 F1/F2 的输入，也看不出
  对正负方向的边际偏置。
- 证据层 A 证明的是总量数据发布日期，协议实际使用的是
  “HS编码×贸易伙伴”细分口径。证据层 B 没有读到一手文件，不能支持第241行
  “细分批次不晚于2025-06-21”的确定表述；第281行“全部披露日早于 T0”也超过了
  当前证据强度。
- 二手收敛证据可用于可行性草案，但不足以充当冻结协议的准入证据。若以后核验
  失败再移动 T0，会重新打开日期选择自由度。

### 发现 2

**发现={条款位置：第二部分候选A，第130–148行；§3.1–§3.4；问题：试点、T0 和
预测对象是在拐点及评估窗口数据已经发生后选定，日期边际的保守性不能消除事件
选择偏差；严重度：高；建议：把本实例固定表述为工作流彩排，不作为历史预测
有效性证据；另行预注册真正未来窗口，或按事前机械规则纳入完整历史事件集合。}**

协议已承认它预测的是“拐点后的延续”，并非预测拐点。这个限定是诚实的，但也
说明试点对象本身是按已发生的结构变化选出的。盲审能检查条款是否仍可调整，
不能把这种后验选题转化为结果盲验证。

### 发现 3

**发现={条款位置：§3.5，第298–339行；问题：F1 的“最近3个月均值”缺少独立
选择依据，第三候选及其他窗口长度没有明确纳入/排除规则；严重度：高；建议：
要么把 F1/F2 定义为不参与有效性裁决的固定计算夹具，要么事先列全候选模型族、
窗口长度和选择规则，并完整报告所有候选，不得在看到评估值后选一个代表。}**

- “最近3个月”可以复现，但“可复现”不等于“选择已预先约束”。文中没有解释
  为什么是3个月而不是2、4、5个月，也没有说明为何不采用扩展均值、中位数、
  阻尼趋势等同样简单的候选。
- 因而无法排除更合适的第三候选被回避，也无法排除 F1 是从多个简单公式中后验
  选出。这里不需要判断哪个候选表现更好；候选集合没有冻结本身就是自由度。

### 发现 4

**发现={条款位置：§3.5 第330–351行、§3.7步骤4第441–447行；问题：F2 与
基准(b)的重合披露诚实，但处置规则改变了原本“同时严格优于两个基准”的门槛，
且没有给出 F2 的封闭三态结果；严重度：高；建议：把 F2 标为“结构性不可比较，
不具备增量价值准入资格”，只保留为计算烟雾测试；不得为 F2 删除基准(b)门槛。}**

- F2 与基准(b)公式相同，应写成
  `MAE_F2 = MAE_b` 或 `MAE_F2 - MAE_b = 0`。第332、446行“F2 相对基准(b)
  的 MAE 恒为0”容易被误读为 F2 对实际值的误差为0。
- §3.7 先规定预测方法必须同时严格优于两个基准，随后又让 F2 只与基准(a)
  比较。这是按模型身份设置的例外，给 F1/F2 使用了不同成功门。
- 如保留 F2 做路径测试，其输出应是“退化对照/不进入成功失败裁决”，而不是
  对基准(a)比较后留下未定义的最终状态。

### 发现 5

**发现={条款位置：§3.6，第353–386行；问题：MAE 的完整案例删除原则本身合理，
但规则是在知道2025-12缺失及当月马来西亚值后新增，不能称为结果信息盲；
严重度：高；建议：将缺失处理拆成固定的MAE规则和固定终点规则，前者可按完整
月份计算并报告覆盖率，后者若2025-12不可观测则判该终点“数据不足”，不要用
2025-11替代。}**

- 不把缺失行填0是正确的；对同一组可观测月份比较各方法和基准的 MAE，也能保持
  比较样本一致。
- 但“写规则前已经知道具体缺失情况”与“规则内容盲”不能同时成立。规则可以是
  机械的，却仍是后验制定。
- 从固定2025-12终点改成“最晚可用月”并不是删除缺失 MAE 观测的必然推论，它
  改变了原预测对象。若连续多个月缺失，这条规则还可能把终点不断前移。

### 发现 6

**发现={条款位置：§3.6第377–386行、§3.7第393–411行；问题：仅凭马来西亚
253,039,858这一高值，不能判断剔除2025-12对“预测Δ为正”的方法有利还是不利；
严重度：中；建议：协议不得给该剔除附加有利/不利解释，应分别报告缺失对方向
判据、MAE和终点判据的影响，并预设敏感性说明。}**

- 美国行缺失，所以该月实际 Δ 的符号和误差均不可观测。马来西亚值较高会提高
  正 Δ 的可能性，但不能确定符号，更不能确定各预测方法相对基准的绝对误差排序。
- 对方向阈值而言，`4/6` 变为 `4/5` 后所需比例从约三分之二升到五分之四，
  对含有正负混合预测的方法更严格；对本协议中全为正的 F1/F2，自洽检查不受
  影响。若步骤4真正检查实际方向，排除一个可能为正但不可确认的月份也不当然
  有利。
- 对 MAE 而言，删除该月可能有利也可能不利，高马来西亚值不能单独回答。

### 发现 7

**发现={条款位置：§3.7步骤1–3，第393–434行；问题：阈值继承关系部分可追溯，
但80%与n<3缺少独立依据，末月替换则是已知缺失后的实质调整；严重度：高；
建议：在v3中逐项登记阈值来源、制定时间和不依赖评估值的理由，并预先写死各
n取值的处理；固定终点缺失时不得自动换月。}**

- `ceil(2n/3)` 在 n=6 时还原 v1 的4/6，是自然且偏保守的整数化处理；没有看到
  v2 为 n=5 放宽这一阈值的痕迹。
- 80%在 v1 已存在，所以不是 v2 因2025-12缺失而新调；但 v1 也是在评估窗口
  已发生后写成，文件没有给出业务、统计或外部协议依据。版本继承不能替代
  事前依据。
- `n<3` 是 v2 新增，文中只称“失去统计意义”，没有解释为什么3个月足够而2个月
  不足。该阈值在已知 n=5 的本例中不产生约束，因此尤其需要独立来源。
- 把2025-12替换为2025-11是有选择性调整痕迹最明显的一项：它由已知的末月缺失
  直接触发，并改变固定终点。

### 发现 8

**发现={条款位置：§3.7步骤2–4，第403–450行；问题：“预测方向自洽”与“实际
方向”拆分后，步骤4没有执行第421–422行承诺的实际方向检查，形成新的判定
漏洞；严重度：高；建议：把预测规格门、实际方向/幅度命中门和相对基准误差门
写成三个不同层次，并给出封闭的三态决策表。}**

- 步骤2只数预测值为正的月份，步骤3也检查预测值是否超过80%阈值。这两步只能
  证明预测声明内部满足目标规格，不能判断预测是否命中。
- 第421–422行称实际值是否满足同一方向阈值会在步骤4核对，但步骤4只定义 MAE，
  没有计算实际正 Δ 月数，也没有检验实际终点是否达到80%。
- MAE 较低不等价于方向与幅度事件发生。因此当前文字可能出现“预测规格自洽且
  MAE优于基准”便判成功，而协议声明的实际方向事件没有被判定。
- 建议改为：
  1. **预测规格登记**：预测向量是否提出了协议要求的方向/幅度主张；不满足时
     是“未提出该预测”，不应记作回测失败；
  2. **实际事件判定**：在可观测性达标时，按预设公式判断实际方向与实际幅度；
  3. **增量价值判定**：在同一月份集合上，预测方法 MAE 严格低于两个非退化
     基准；
  4. 任一实际目标不可观测时进入“数据不足”，不要用替换月份改变目标。

### 发现 9

**发现={条款位置：状态声明第1处第3–9行、第2处第183–188行、第3处第534–540行，
以及§3.5、§3.6、§3.7步骤1、试点可行性支撑证据第493–512行；问题：三处
“未运行”声明被正文部分实质违反，评估表构成揭盲；严重度：高；建议：重写
状态声明并制作不含评估金额的盲审包，由数据保管方只提交存在性、缺失模式和
哈希/行数证明。}**

裁决如下：

- **尚未发生的部分**：正文没有计算评估窗口实际 Δ，没有计算预测误差或 MAE，
  也没有给出回测最终分类。对此，“尚未执行实际比对”成立。
- **已经发生的部分**：§3.5 已代入历史信息并生成 F1/F2 逐月预测向量；
  §3.6 与§3.7步骤1已经检查评估数据完整性、识别具体缺失月并确定 n=5；
  第493–512行直接列出评估窗口两组实际金额。因此第185行“本文档不运行任何
  预测”不成立，“协议未运行”也至少需要改成“协议已运行到实际比较前”。
- **揭盲裁决**：列出计算实际 Δ 所需的两列逐月实际金额，已经向协议作者和
  审查人暴露结果输入。即使没有执行减法或 MAE，它仍构成实质揭盲；把这些数字
  命名为“可行性支撑证据”不会恢复信息隔离。
- v3 应精确写为：“已完成后验选题、预测函数计算和数据完整性检查；评估输入
  已在 v2 暴露；尚未执行实际 Δ、MAE及最终分类。”如需重新进行结果信息盲的
  条款审查，应换用未见金额的审查人和脱敏审查包；这仍不能消除协议作者已知
  历史结果这一固有限制。

### 发现 10

**发现={条款位置：§1.1第⑥项、§3.7步骤4；问题：最终输出状态没有完全闭合；
严重度：中；建议：给 F1、F2/退化对照、终点缺失、方向命中但MAE不优、MAE优
但实际方向未命中等组合逐格定义三态结果。}**

§1.1规定输出只能是“成功/失败/数据不足无法判定”，但§3.7又引入“方向正确但
无增量价值”“退化对照，不构成证据”等没有映射回三态的标签。尤其 F2 被免除
一个基准比较后，第三方无法按现文得到一致的最终分类。

## v3 重审前的最低修改清单

1. 用一手证据闭合细分口径公开日；若不能闭合，停止在 T0 准入门。
2. 冻结预测函数候选集合与选择依据；F2 不参与增量成功裁决。
3. 保留完整月份 MAE 规则，但取消“末月缺失便以前一可用月替代”的规则。
4. 分开写预测规格、实际方向/幅度命中、相对基准 MAE，并补齐三态决策表。
5. 将状态改为“已执行至实际比较前”，删除盲审包中的评估金额。
6. v3 另存，不覆盖 v2；通过复审前不得计算实际 Δ/MAE。
