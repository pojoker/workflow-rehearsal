# 内容层提案对抗评审（Codex）

> 评审目标：证伪优先，不替提案补强叙事。  
> 评审对象：`logs/anomalies.md` 末条、`flows/out/content-layer-sample-lieqi.md`、
> `flows/discussion-content-layer.md`，并以冻结的 `flows/ROADMAP-v1.7a.md` 为兼容性基线。  
> 三态：**通过 / 有条件通过 / 不通过**。  
> 总结论：**方向有条件通过；当前五类 schema、④类挂边方案、直接全量抽取均不通过。**

## 一、逐项三态结论

| 评审项 | 结论 | 一句话裁决 |
|---|---|---|
| ① 内容层会不会稀释证据纪律 | **有条件通过** | 只有把技术锚与关系边准入做成互不替代的双闸，内容层才可成立；“立场标注”本身挡不住越级。 |
| ② 五类 schema | **不通过** | 五类不互斥、多条非原子，⑤还是横切立场而非事实类型；④缺少阻断跨图传递的结构。 |
| ③ 发行人自述污染控制 | **不通过** | 当前只有展示性标签，没有来源链、时态、验证态、晋级规则和机器校验，标签很容易在摘要、聚合与前端中丢失。 |
| ④ 五招股书+年报技术章节全量抽取 | **不通过** | 现阶段只证明“可抽”，未证明去重后的知识增量与复核单位经济学；先全量会把 schema 债放大。 |
| ⑤ 与 v1.7a 四段制相容性 | **有条件通过** | 它是**新增层**，不是冻结 v1.7a 第1段的既有治理还债；可在 v1.7b 复用“四段执行法”，不可静默塞进 v1.7a。 |

## 二、① 证据纪律：技术锚不能成为关系四件套的弱化通道

样品已经提供反例：

- C11 的同一句同时包含“0.5 微米设备精度”和“向中际旭创完成交付”。前者是
  技术参数，后者是具名交易语义。
- C10 同一句同时包含精度、国内一流水平、行业龙头客户批量采购和“核心装备”。
  它跨越参数、竞争评价、匿名客户关系与重要性评价四种主张。
- C29–C31 虽位于招股书技术章节，却是转载咨询机构的份额/排名主张，并非发行人
  亲历的技术事实。

因此，“招股书第五节=T1”只说明**文件身份与责任主体**，不能自动把其中每句话
都变成同等级的一手事实。招股书内仍混有发行人可观察事实、行业概括、第三方转载、
预测、计划和营销评价。

### 必须冻结的双闸

1. **内容事实闸**：技术类锚只准生成 `content_claim`，最少应有原子主张、原文引语、
   文件与页码、锚点、披露方、文档日期/有效期、原始来源链、立场、时态、核验状态
   和抽取日期。
2. **关系事实闸**：凡主张包含具名对手方、客户/供应商身份、采购、销售、交付、
   中标、金额或占比，必须转入关系候选闸。事实核查四件套
   （URL+检索日期+命中引语+判定）不得省；要入正式关系边，还必须继续满足现行
   `{证据文件, 年份, 披露方, 占比或金额, 锚点URL, 边等级}`。技术锚不能补缺金额、
   年份、对手方或边等级。
3. **无隐式晋级**：未过关系闸的关系语义只能是 `relationship_lead` 或内容上下文，
   不得因所在文档是招股书、已有另一条供货边，或前端需要展示而晋级。

按此规则，C11 可保留“发行人称首台耦合设备精度为0.5微米”的内容事实；其“向
中际旭创交付”若没有占比或金额，只能进入关系线索，不能单独生成正式边，也不能
给既有“猎奇→旭创”边补上具体型号。

## 三、② 五类 schema 的结构缺陷

| 现有类型 | 主要缺陷 | 最低修正 |
|---|---|---|
| ① 工序步骤 | 把行业通用流程、工序顺序、发行人产品覆盖和“核心/最易不良”等评价混在一条；缺适用对象、前后序和规范性来源。 | 拆成 `process_step`、`process_sequence`、`issuer_process_coverage_claim`；评价词单列。 |
| ② 技术参数 | 缺 `metric/value/unit/tolerance/test_condition/object_model/as_of/status`；设备精度、加工精度和工艺能力易被当成同一指标。C10/C11还夹带客户关系。 | 参数结构化并原子化；关系片段强制分流。 |
| ③ 产品代际 | 把速率分类、产品代际、市场成熟度、客户测试、预研和未来预测放在同类。C19 的“规模交付/测试/预研”是状态主张，不是单纯代际。 | 至少拆 `generation_taxonomy`、`product_compatibility`、`market_maturity_claim`；强制 `as_of` 与 `actual/planned/forecast`。 |
| ④ 设备-工序映射 | 把“设备类别/型号适用于某工序”误当成“某客户从该供应商买了该型号/用于该工序”的可传递属性；缺交易级共同键。 | 内容图只建 `equipment_model/category → supports_process`；与关系边默认不传递，交易级挂接另设硬闸。 |
| ⑤ 发行人竞争陈述 | “发行人自述”是所有类型都可能具有的**立场维度**，不是与前四类并列的事实类型。把它单列会让前四类中的自述看起来更客观。 | 删除为同层类型，改成每条必填的 `claimant_stance/source_origin/verification_state`；市场份额、竞对、领先评价另设 claim subtype。 |

另有两个样品级信号：

- 讨论页称“32条五类”，样品汇总为34条，且又写“34/34引语回源”。计数基线已漂移。
- “一条有引语”不等于“一条只有一个事实”。C01、C03、C05、C10、C15、C18、
  C20、C28 等均含多个可独立真假的谓词；按行计回源率会高估覆盖率。

### ④类的不可传递公理

必须把三种关系拆开：

1. `发行人 → manufactures/offers → 设备型号`
2. `设备型号/类别 → supports_process → 工序`
3. `供应商 → transacts_with → 客户`

前两条与第三条**不可做传递闭包**：

> “猎奇在册有 HP-EB3300” + “猎奇向旭创供货”
> **不能推出**“旭创购买 HP-EB3300”，更不能推出“该笔交易用于 1.6T 共晶贴片”。

只有同一披露或可核对的同一合同/订单/交付记录同时给出
`供应商+客户+型号（或明确设备类别）+期间/交易标识`，且关系边本身已过现行准入，
才允许建立 `edge_claim_link(scope=transaction_specific)`。否则最多
`scope=context_only`，前端不得把它画成关系边属性。

## 四、③ 发行人自述的污染路径

当前“立场标注”是文本约定，不是控制。至少有六条可复现的污染路径：

1. 抽取时写“发行人称”，报告摘要或卡片压缩时删掉主语，变成无条件事实。
2. 内容图与事实边同色、同权重展示，读者把“有锚”误读成“已独立核验”。
3. 多家招股书重复引用同一咨询机构，被聚合器误算成多源交叉验证，形成回声室。
4. 产品表中的能力参数与客户表中的关系边按公司名自动 join，生成不存在的型号交易。
5. “正在研发/预计/进入测试”在标准化时丢失时态，变成当前量产能力。
6. 发行人编制的竞对表、价值量和“领先/替代/核心”等评价进入行业本体，反过来给
   同一发行人的竞争结论作证，形成自证循环。

最低防线应是机器字段和晋级规则，而非写作提醒：

- 每条必填 `claimant`、`source_origin=issuer_observed|third_party_reprinted|
  forecast|opinion`、`temporality=actual|planned|forecast`、
  `verification_state=unverified|single_source|independently_corrobated|contradicted`。
- 转载统计必须记录原始报告身份和可访问状态；拿不到原报告时不得计独立来源。
- `issuer_claim` 默认不承重、不参与共识票数、不向关系边和通用行业本体自动晋级。
- 前端的立场、时态和核验态必须在主视图可见，不能只藏在 hover 或详情页。

## 五、④ 全量抽取的成本收益

“原料零采集成本”不等于“内容层零成本”。样品日志显示34条约40分钟，只测到
**初抽速度**；尚未计入原子化、来源链拆分、跨年去重、冲突处理、关系分流、人工
复核和前端适配。尤其年报技术章节存在跨年复制，按全文逐年抽会把重复内容伪装成
知识增量。

全量前应先跑一个预登记的有界试点：

- 范围：两份结构差异明显的文件；先不扩到“五招股书+历年年报”。
- 上限：每份4人工小时或100条原始候选，以先到者停。
- 报告：原子主张通过率、去重后唯一主张/人工小时、重复率、冲突率、关系语义分流率、
  原始来源可得率、最终可展示率。
- 淘汰线：连续2人工小时零新增合格唯一主张，或去重后噪声/重复超过90%。
- 年报策略：招股书建立基线后只抽年度增量；无触发不做全文重扫。

只有试点证明“去重后唯一且合格的产业知识/人工小时”为正，并验证双闸无漏放，
才能进入全量。当前直接全量抽取结论为**不通过**。

## 六、⑤ 与 v1.7a 四段制的相容性

`logs/anomalies.md` 已明确内容层“属前提级变更，须经三方讨论后决定，不并入现行
v1.7a四段制”；冻结版 v1.7a 第1段列出的也是现有关系图谱的基线、实体、边 subtype、
股权/担保、指标和代码治理债。把内容层改称“第1段还债”会绕过版本纪律。

裁决应是：

- **架构上：新增层。** 新增 `content_claim`、设备/工序/代际实体及内容关系；
  不改写为 `output/edges.csv` 的附加列，也不把它并入供货集中度。
- **流程上：复用四段法。** 在 v1.7b 中可按“第1段冻结 schema 与双闸 →
  第2段有界试点 → 第3段只吸收有效机制 → 第4段事件/年度增量监测”执行。
- **版本上：不是 v1.7a 第1段还债。** 即使 schema 冻结动作形式类似治理，也是在
  新层启动时偿还**新增架构债**，应显式版本化。

## 七、最终准入条件与可推翻条件

当前建议：**不立即开发全量抽取与挂边；先冻结 schema、双闸和不可传递校验，再跑
有界试点。**

以下条件全部满足后，可把总裁决从“方向有条件通过”提升为“通过”：

1. 五类重构为原子、正交 schema，⑤改为横切立场字段。
2. 任一具名关系语义能被校验器强制分流，技术锚不能替代关系准入字段。
3. ④类实现不可传递校验，并有“目录型号+既有客户边”反例测试且必须拦截。
4. 发行人自述在抽取、聚合、报告和前端四处均不丢立场/时态/核验态。
5. 有界试点提交完整漏斗和单位经济学，达到事前冻结的继续线。
