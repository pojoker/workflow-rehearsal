# CLAUDE.md — 数据研究 workflow 彩排任务

你（Claude Code）要执行的是一次**端到端彩排**：用一个真实研究问题跑通一套
数据研究 workflow，产出研究结论 + 完整执行日志。之后由 DISTILL.md 的流程
从日志中蒸馏出正式 SOP。**SOP 从执行记录里长出来，不预先编纂**——这是本
任务的第一设计原则。

## 研究问题（彩排载荷）

> 光模块设备产业的真实结构是什么——谁在给谁供货，每条关系的披露证据是什么？

产出物：`output/光模块产业结构-v0.1.md` + `output/nodes.csv` + `output/edges.csv`

## 目录

- `REHEARSAL.md` — 彩排协议：五个阶段的执行序、质检门、预算与停机规则
- `DISTILL.md` — 蒸馏协议：彩排结束后如何从日志产出 SOP
- `seed/` — 本次彩排的种子数据（前期会话已验证的边与结论，**勿重复劳动**）
- `assets/MANIFEST.md` — 需要用户放入的既有资产清单（skill、收割库、信源表）
- `logs/` — 彩排日志（格式见 REHEARSAL.md §日志纪律，蒸馏的唯一原料）
- `output/` — 研究产出

## 全程纪律（优先级高于效率）

1. **日志先于产出**。每个动作先写日志再执行下一步。没有日志的步骤视为未发生。
2. **彩排中禁止造新工具**。遇到摩擦（想写脚本、想建库、想改协议）→ 记入
   `logs/friction-backlog.md`，继续手动走。工具决策留给蒸馏阶段用摩擦证据裁决。
3. **边的准入纪律**：每条入图的边必须带 {证据文件, 年份, 披露方, 占比或金额,
   锚点URL, 边等级}。边分四级：实边（强制披露实名）/ 半边（单侧披露+对方匿名）/
   推断边（B工序产出，标注判定等级）/ 禁止（研报产业链图、新闻据悉、模糊确认）。
4. **判定纪律**：事实核查遵循四件套（URL+检索日期+命中引语+判定类别）；
   "没找到"必须附检索轨迹才算数。
5. **诚实边界**：付费墙/登录墙内容标记不可验证，不绕行不假装。
6. 遇到本文件与 REHEARSAL.md 冲突，以 REHEARSAL.md 为准并把冲突记入日志。
