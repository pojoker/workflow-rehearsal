## 1. 权限边界

### 可以读取

- `RQ000`：允许回答；

- `TQ001`、`TQ004`：只用于识别技术路线内容并把它排除出本轮，不允许回答；
- 本研究包的 `sources.md`。

### 可以输出

- 一段 RQ000 的“对象口径声明”；
- 最多 3 条物理体系的原子主张草案；
- 最多 3 条研究注记，且必须挂到现有 RQ/PQ/TQ/WQ，不得发新问题 ID；
- 证据不足、来源冲突和应停止之处。

### 禁止

- 回答 PQ001、PQ002、TQ001 或 TQ004；
- 输出技术路线 KN、WHY、公司能力群、供货或投资结论；
- 新增 CQ/PQ/TQ/WQ 编号；
- 访问本研究包之外的本地文件；
- 联网、运行 shell、Python 或任何校验命令；
- 修改或创建文件。

## 2. 允许工具

Pi 进程不开放任何工具，并关闭项目 context 文件自动加载。`contract.md` 与 `sources.md` 作为初始
输入附件注入；Pi 不能再读取工作区、联网、执行命令或写文件。来源范围由进程能力机械限制，
而不是依赖提示词自觉。

## 3. 来源与主张口径

- 只能引用 `sources.md` 中列出的来源 ID；
- “公司口径”只能证明该公司如何定义或描述对象；
- “MSA 现行页面”只能证明该形态规范覆盖什么；
- “IEEE 项目目标”只能证明工作组设定的支持目标，不能证明已批准 PMD、物理极限或商业采用；
- 不允许把多来源拼成“唯一标准定义”；如需组合，只能标为 `研究框架`；
- 每条原子主张只能属于一个体系，本轮只能是 `物理知识` 或 `研究框架`。

## 4. 输出格式

按以下顺序输出中文 Markdown：

1. `RQ000 口径声明`：不超过 180 字；
2. `原子主张草案`：最多 3 条，每条含：
   - `draft_id`
   - `system`
   - `question_id`（只能 RQ000）
   - `claim_type`（直接事实 / 公司口径 / 研究框架）
   - `statement`
   - `evidence_ids`
   - `boundary`
   - `would_mark_covered`（固定为 false）
3. `研究注记`：最多 3 条，每条含：
   - `attach_to`
   - `note`
   - `trigger_evidence_ids`
   - `why_existing_question_can_hold_it`
   - `expected_answer_shape`
   - `stop_condition`
4. `拒绝的推论`：逐条说明为什么不能从给定证据推出；
5. `缺口与停止结论`：本轮是否已足以形成可审草案，以及为什么停止。

不得输出 append-ready `knowledge.yaml`，因为本轮尚未解决存量 KN 兼容和问题验收合同。
