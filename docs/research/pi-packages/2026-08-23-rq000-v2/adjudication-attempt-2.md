## 3. 内容返修项

### A1：`system: 研究框架` 不是合法知识体系

D3 把 OSFP MSA 事实的 `system` 写成“研究框架”。项目只有“物理知识”和“技术路线”两套知识
体系；“研究框架”应是主张类型或展示方法，不能成为第三体系。

裁决：D3 如继续，应改为 `system: 物理知识`，并保持“仅证明 OSFP MSA 规范覆盖面”的边界。
下一版合同也应把 `system` 限为现有体系，不再允许“研究框架”作为 system 值。

### A2：RQ000 注记不应把 IEEE 项目目标列入最终答案层

注记 1 的 `expected_answer_shape` 包含“IEEE 目标口径”，但本轮已正确判断 S5 属技术路线材料。
RQ000 最终对象口径不需要用链路距离目标定义自身。

裁决：从 RQ000 答案形态删除 IEEE 目标；S5 只保留为技术路线侧排除记录。

### A3：S5 更适合 TQ005 的来源注记，不应提前回答 TQ001

Pi 将 S5 挂到 TQ001，虽然没有起草路线答案，但该目标更具体地属于产品/链路标准轴 TQ005。
由于本轮合同没有允许读取 TQ005，不能要求 Pi 正确完成精细路由。

裁决：本轮注记只作为“从 RQ000 排除”的过程记录，不提升到问题树。后续路线合同应允许读取
TQ004–TQ005，并把 S5 归到 TQ005。

### A4：S4 仍缺正式 web snapshot

D3 已正确声明缺口。因此 D3 只能存在于研究包，不能进入 `knowledge.yaml`。

裁决：维持 draft；若正式研究 RQ000/PQ001，应先保存 `corpus/web/` 快照，并使用
`web_snapshot` 锚型。

## 4. 对循环的结论

本轮证明以下机制可行：

- 先冻结来源，再让 Pi 起草，可以消除开放检索带来的来源漂移；
- 无工具模式可以机械保证 Pi 不读包外文件、不联网、不写入；
- 明确 read/answer 权限后，Pi 没有再替 TQ001 起草路线答案；
- 研究注记可以吸收细问题，不必让问题树自动新增节点；
- `would_mark_covered: false` 可以阻止草案误触发读者页“已覆盖”。

本轮同时证明：即便流程边界变严，语义裁决仍不可省略。Pi 仍可能引入第三体系值、把被排除来源
写进预期答案层，或把来源注记挂到过宽的父问题。因此 Pi 适合作为起草者，不适合作为验收者。
