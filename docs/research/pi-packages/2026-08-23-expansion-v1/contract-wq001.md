# WQ001 draft-only 桥接合同

## 1. 目标与边界

- 唯一回答目标：`WQ001 系统需求为什么会变成这些物理约束？`
- 关系类型：`need_to_constraint`
- 只允许消费本包经 Codex 裁决后的 PQ002、TQ002 草案及其冻结来源。
- 不写 `why_links.yaml`，不写任何 canonical，不生成新问题 ID，不改变覆盖状态。

## 2. 验收条件

1. 每条桥接关系必须同时有 route-side 需求证据和 physical-side 机制证据。
2. 使用固定链条：`场景需求 → 接口/链路约束 → 物理机制 → 可观察指标`。
3. 必须标明关系强度：直接证实、规范结构支持或受限推论；不得把受限推论伪装成事实。
4. 只桥接证据足够的关系；成本、维护若缺物理机制或量化证据，应保留为空缺而非补写。
5. 输出只使用现有 QID：`WQ001`、`TQ002`、`PQ001`、`PQ002`、`PQ009`。

## 3. 禁止推论

- 不得从约束直接跳到 EML、SiPh、LPO、CPO 等路线选择。
- 不得从路线选择直接跳到公司受益。
- 不得生成第三套知识主干；WQ001 只是两套知识体系之间的关系。
- 不得把相关性写成因果性；证据不足的桥不输出。

## 4. 输出格式

只输出中文 Markdown，包含：结论摘要、桥接关系表、关系草案、未桥接项、拒绝的推论、
自检矩阵和停止结论。所有草案写 `would_mark_covered: false`。
