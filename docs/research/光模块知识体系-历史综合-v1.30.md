## 2. 用户要建立的总体结构

知识体系有两套主干，并由 WHY 关系连接：


目标不是堆砌 EML、SiPh、LPO、CPO 等热词，而是从“什么是光模块”开始，让问题逐层生长到技术路线和产业影响。

## 4. 当前已经形成的知识

### 4.1 基础原理：稳定解释

- 光模块位于处理电信号的芯片与传输光信号的光纤之间，承担双向电光转换。
- 发送方向完成：整理电信号 → 提供高速驱动 → 产生并调制光 → 把光送入光纤。
- 接收方向完成：接收光 → 光电探测 → 放大微弱电信号 → 恢复为主机可处理的信号。
- 供电、管理、PCB/载体、机械保护和散热属于支撑系统，不应与核心收发链混成一条信号流。
- “共同功能”不等于“所有产品具有相同独立零件”；一个功能可以被集成、拆分或省去。

### 4.2 典型物理组成：稳定功能骨架，具体 BOM 仍为条件化

当前按功能整理为九类：

1. 信号处理芯片；
2. 高速驱动芯片；
3. 光源与调制器；
4. 合光与分光结构；
5. 微型光学与光纤接口；
6. 光电探测器；
7. 微弱信号放大器；
8. 管理与控制芯片；
9. 电路板、外壳与散热系统。

边界：这是一张功能—常见部件地图，不是所有光模块的统一 BOM。

### 4.3 关键连接：典型候选

当前识别六个关键连接环节：

1. 主机接口 → 电路板 → 信号处理芯片；
2. 信号处理芯片 → 驱动/接收电路；
3. 驱动芯片 → 发光或调制器件；
4. 光源 → 集成光路；
5. 光芯片/光器件 → 光纤；
6. 光电探测器 → 微弱信号放大器。

必须始终区分：信号怎样流动，与工厂怎样把零件连接起来，是两张不同的图。

### 4.4 制造与装配：典型候选

已形成四类代表性部件制造卡：

- 化合物半导体发射芯片，以 EML 为例；
- 硅光子芯片；
- DSP、Driver、TIA 等电芯片；
- FAU、透镜等精密光学件。

模块装配的典型顺序为：

```text
准备电路板/载体 → 贴装芯片和元件 → 高速电互连
→ 安装光源或光芯片 → 光路对准 → 固定光纤
→ 外壳和散热装配 → 校准、老化和误码测试
```

边界：典型流程不代表所有厂商、所有产品采用相同设备和顺序。

### 4.5 提速压力：稳定因果骨架，具体强弱仍需对象化

当前因果链为：

```text
AI 集群扩大 → 芯片间数据交换增加 → 交换容量与端口速率提高
→ 模块总速率和单通道速率提高
→ 电通道损耗、功耗、热、光器件带宽、封装和测试压力提高
→ 不同技术选择的相对价值发生变化
```

- 800G、1.6T、3.2T 表示总传输速率层级，不是存储容量。
- 总速率通常由多条并行通道共同完成，因此必须继续说明通道数和单通道速率。
- 禁止无条件写“800G 已经不够”“铜已经失效”“3.2T 必然采用 CPO”。

### 4.6 技术路线分类：当前最稳定的研究成果

技术路线至少拆成六个问题层次：

| 层次 | 回答的问题 | 例子 |
|---|---|---|
| 链路需求 | 传多快、多远 | 800G、1.6T、DR、FR |
| 光链路组织 | 并行还是波分 | DR8、FR4、parallel、WDM |
| 电处理职责 | 模块处理多少信号恢复 | retimed、LPO、LRO |
| 光子实现 | 怎样发光、调制、探测和集成 | EML、SiPh、DML、PIN |
| 光学放置 | 光学离交换芯片多远 | pluggable、NPO、CPO |
| 产品形态 | 怎样装、怎样接 | OSFP、QSFP-DD |

关键纠偏：

- EML 是发射器件实现；SiPh 是光子集成平台，二者不是严格同粒度二选一。
- LPO/LRO/retimed 主要描述电信号处理职责，不是光子平台。
- NPO/CPO 描述光学放置位置；OSFP/QSFP-DD 是可插拔外形。
- DR8/FR4 描述链路组织，不能自动推出 EML、SiPh、LPO 或 CPO。

### 4.8 WHY 与优劣势：机理候选

已建立的分析格式：

```text
上游需求/约束
→ 某项选择的相对价值提高
→ 组件、接口、制造和测试变化
→ 获得某项优势
→ 责任转移或出现新瓶颈
→ 供应链能力要求变化
```

当前重点小样为“为什么把 LPO 与 SiPh 组合起来观察”。已有机理解释，但尚缺同速率、同距离、同温度、同 FEC/BER 的功耗、成本、良率和时延受控比较，不能给出无条件胜负。

### 4.9 主流与公司：部分可答

- 可以说 800GbE 已是高速数据中心模块的重要主流速率层级。
- 不能给出 800G 内部 EML、SiPh、LPO、retimed 等路线的可靠份额排序，因为缺少同时间、同市场、同产品边界和同统计指标的共同分母。
- 可以确认公司具有某项产品、器件、平台或设备能力。
- 除非证据绑定同一具体产品和路线，不得把公司能力升级为精确供货关系或客户部署。

### 4.10 前面板可插拔共同约束：研究候选

Q-UP-02 已形成可供外部审阅的候选回答，但尚未晋升正式知识：

- 对 802.3ck/802.3df C2M，官方形成材料把 AC-coupling 功能放在模块内部；TP1a、TP1、TP4、TP4a 是参数相关的合规/测试参考面，不是电容物理位置。模块内部可为分立或 on-die 实现。由于本轮未直接取得已发布标准正文，该结论为 `partially_confirmed`。
- QSFP-DD Hardware Specification Rev 7.1 直接确认 QSFP-DD、DD800、DD1600 的模块端均为 76 pads，但三代机械和 host footprint 并不完全相同；DD1600 的 1×1 host 侧为 104 contacts。
- module body、pull-tab/handle、cage/connector、bezel opening 与 host footprint 必须分对象记录；推荐性开口和 informative 总长不能升级为统一强制尺寸。
- 精确尺寸、完整 pin table 与剩余未知保存在 `docs/research/pi-packages/2026-08-27-q-up-02-closure-v1/`。该研究包仍缺最终 IEEE 正文锚点和冻结证据快照。

### 4.11 DR / FR 链路边界：研究候选

Q-UP-01 已形成可供外部审阅的候选回答：

- 裸写 `DR8` 或 `FR4` 不足以定义路线，必须绑定 aggregate rate、完整标准对象、发布组织和版本/成熟度。
- 已发布对象包括 `400GBASE-DR4`、`800GBASE-DR8`、`400GBASE-FR4`；`800GBASE-DR4`、`800GBASE-FR4-500`、`800GBASE-FR4` 截至本轮仍是 P802.3dj draft；800G Pluggable MSA `4×200G-FR4` 是组织规范，不等于 IEEE PMD。
- PMD 可定义 lane、波长、光纤、reach、FEC/BER 与 MDI，但不定义 form factor、电处理职责、EML/SiPh、TEC、BOM 或商业成熟度。
- 下一轮 parallel vs WDM 的受控比较应优先使用同属 P802.3dj 的 `800GBASE-DR4` 与 `800GBASE-FR4-500`，尽量固定 800G、4×200G、500 m 和 FEC 代际。

完整字段和 unknown 保存在 `docs/research/pi-packages/2026-08-27-q-up-01-link-boundary-v1/`。由于正式标准正文/草案和证据快照仍有可及性缺口，本节不晋升正式知识。

### 4.12 Parallel vs WDM：研究候选

Q-UP-06 已形成架构层候选回答：

- P802.3dj draft `800GBASE-DR4` 与 `800GBASE-FR4-500` 可在 800G、4×约200G、106.25 GBd PAM4、500 m、FECo-only 边界下比较；仍须保留 draft 状态。
- DR4 主要在空间维度保持 lane 可分辨，外部为 4 Tx + 4 Rx active fibers；FR4-500 主要在光谱维度保持 lane 可分辨，使用四个 CWDM wavelength ranges 和每方向单纤，并需要等价合分波功能。
- 规范要求的是功能，不锁定 AWG、TFF、PLC、SiPh、EML、TEC、form factor 或电职责。
- 当前最稳健的 WHY 候选是“复杂度转移”：DR 把责任放到多纤 mapping/connector/阵列耦合，FR 把责任放到 wavelength/passband/mux-demux/common path。成本、功耗、良率、cycle time 和设备净增量仍未知。
- Kimi/Cursor 外部审阅均为 `PASS_WITH_FIXES`。新增发现是早期 DR/FR 提案 reference receiver 为 FFE11，而 FR4-500 baseline 为 FFE15；当前 D3.x 是否统一仍未知，所以只能把 TP2/TP3 **概念边界**视为共同，不能把数值测试配置视为完全相同。
- 产品反例证明 WDM 可以存在离散/集成和无 TEC 路径，只能否定必然性，不能填充 800GBASE-FR4-500 的统一 BOM。
- 对 KN006 的审计发现：同一招股书有 AWG 直接材料，但当前证据卡只挂了 splitter 段落；结构校验不等于证据蕴含主张。
- QX-11 已形成 candidate answer：同一招股书可以分别支持 PLC splitter 工艺、AWG 结构/WDM 功能和二者共享部分 PLC 材料/刻蚀平台三条窄主张；当前 KN006 的“主流”与教学类比不由现有证据承重。已形成 3 条 split 候选并通过机器预检，仍为 NOT PROMOTED，正式 KN006 未改。

完整裁决、候选 claim/WHY 和 12 个专家问题保存在 `docs/research/pi-packages/2026-08-30-q-up-06-parallel-vs-wdm-v1/`，尚未晋升正式知识。

### 4.13 FR4-500 具名产品对象闸：研究候选

QX-03 已找到一个可追索的具名对象：Juniper `ORHS-2X800G-FR4-P`，part number `740-189771`。

- Juniper HCT 将其列为 2×800G-FR4、Dual Duplex LC/UPC，并给出 QFX5250 平台与 Junos OS Evolved `25.2X100-D20` 引入记录。
- 同一 HCT 兼容信息列出：inner FEC enabled 时服务 2 km `800GBASE-FR4`；inner FEC bypassed 时服务 500 m `800GBASE-FR4-500`。
- 同一命名 SKU 的两种 800G 模式 host lane 都是 106.25 GBd；FR4-500 media lane 为 106.25 GBd，FR4 为 113.4375 GBd，且 Tx/Rx 门限不同。它不只是一个 FEC boolean，但尚未证明同一硬件 revision 可现场切换。
- SFF-8024 Rev 4.14 为 FR4-500/FR4 分配不同的 `MediaInterfaceID 0x79/0x7A`；模块实际 AppSel 排列仍必须读取 CMIS。
- CMIS 5.3 CDB `0x0050` 可按 application 返回最大功耗与部分光学/BER 阈值，已经形成可执行 page-dump 合同。
- 官方资料未披露 mux/demux 类型、TEC、laser/filter 架构和温度 margin；第三方 compatible 产品的 SiPh 声称不能继承到 Juniper SKU。
- exact-SKU 专利、认证照片、ODM/供应商正式披露和 teardown 公开追索均未命中；结论只能是 `public_evidence_insufficient`，不是“不存在”。
- HCT 整页 HTML 哈希会随请求变化；规范化产品对象的语义哈希连续三次稳定。后续证据快照应同时保存原始响应和语义提取，不能只依赖整页哈希。

因此对象闸状态仍为 `partial_not_passed`：已经从“没有对象”推进到“有具名对象、模式差分与可执行观测合同，但内部实现未知”。Q-UP-04 的 TEC 裁决只能写 `public_evidence_insufficient`。若拿不到真实模块/官方 CMIS dump，可先并行研究不依赖该对象的 Q-UP-03 或 Q-UP-05。研究包位于 `docs/research/pi-packages/2026-08-30-qx-03-fr4-500-sku-v1/`。

### 4.14 Host 电边界与 retimed / LRO / LPO：研究候选

Q-UP-03 已形成候选回答并经延续上下文的 Kimi、Cursor 独立审核，均为 `PASS_WITH_FIXES`；必修项已返修：

- “Host 足够强”不是单一 dB、tap 数或 SerDes 代际，而是端点合规、channel impairment、Tx/Rx 均衡、module transfer function、FEC/BER/FLR、控制面、适应收敛和 exact pairing 互通组成的向量。
- Full retimed 在 Tx/Rx 两方向用模块 CDR/retiming 切断模拟误差链；Tx-retimed/Rx-linear 只在 Tx 切断；LPO 两方向都需要 Host 与 module 联合闭合端到端链路。
- LPO MSA 的 `LRO` 与 OIF 的 `RTLR/TRO` 指向 Tx-retimed/Rx-linear，但正式术语未跨组织统一；营销标签不得替代具名产品方向图。
- `retimed` 不自动证明 module 内 ADC/DAC DSP、FEC 或 gearbox；reference CTLE/FFE/DFE 也只是合规测试模型，不是实际 BOM。
- 100G/lane 已有正式 LPO、CEI-112G-LINEAR 与 RTLR 规范边界。200G/lane 仍必须拆成在研规范、产品 listing、架构级 demo/plugfest observation，不能统一写成成熟部署。
- Amphenol/XGIGA 找到三类 1.6T exact products，但最高主要为 listing。OIF ECOC 2025 的 LPO 演示材料存在 `OP13LI8-005D` 与 DR8/MPO-16 变体冲突，exact-SKU 不晋升 demonstrated。
- Ethernet Alliance HSN 2025-12 224G Plugfest 的 LPO/LRO 合并结果为 15/16 link-up；报告提交至 P802.3dj，但不是 IEEE Task Force 自办 workshop，也没有公开 exact pairing matrix。

完整裁决、职责矩阵、33 条 Host/channel 边界、exact products、候选 claims 与 12 个专家问题保存在 `docs/research/pi-packages/2026-08-30-q-up-03-host-electrical-architecture-v1/`。本节仍不晋升正式知识。

### 4.15 Retimed / Tx-retimed-Rx-linear / LPO 优劣：研究候选

Q-MID-01 已在同厂、同 1.6T、同 OSFP、同 2×DR4/500 m 的产品 listing 横截面上形成候选回答，并经延续上下文的 Kimi、Cursor 两轮审核，最终均为 `PASS`：

- Amphenol/XGIGA 三款 exact products 的模块 nameplate ceiling 分别为 `<30 W`、`<20 W`、`<11 W`；这是供应商规格上限的同向观察，不是受控实测，也不证明职责减少导致功耗下降或系统同比节能。
- `OP13PI8-005D` 只直接确认含 retimer 与 5 nm DSP，Tx/Rx CDR 分项仍 unknown；full-retimed 双向切断是架构机制，不能偷渡成该 SKU 的公开字段。
- Full retimed 的候选价值是切分误差链和保留分段诊断边界；代价候选是模块功耗、热和高速 data-path 功能更多。实际 pairing 成功率、MTTR、功耗和时延未公开。
- Tx-retimed/Rx-linear 是方向不对称的职责选择，不应简称“半个 LPO”；其 Tx 保留局部边界、Rx 把恢复责任交给 Host，但真实系统折中尚无受控证明。
- LPO 的公开候选优势是模块功耗上限更低；它不是“无诊断”或“无需配置”，而是把位级主观测移到 Host，并保留模块模拟/光健康量。100G/lane 的端口校准、CMIS-VCS、自适应和 store/recall 只作机制旁证，不证明 1.6T exact products 已实现。
- Cisco 800G 系统演示、Arista 800G qualification 与 224G plugfest 都是相邻证据，不能补齐 1.6T exact pairing、系统功耗、温箱、yield、RMA 或 deployment。
- 当前真正缺口已改写为 9 个带验收合同和反证条件的专家问题，重点测 module/Host/PSU/fan 分项、统一测点 latency、VCS/time-to-link、温漂、fault-injection MTTR、HVM cycle-time/yield 与 1.6T qualification/deployment。

11. **可服务性矩阵门**：`tools/research/check_serviceability_matrices.py` 把每个对象拆成 failed unit、attach、replacement class、actor、location、power/fiber state、tools、steps、post-test、MTTR 与 RMA boundary。至少两个对象必须有真正承重的 replacement-class 证据；UNKNOWN 必须绑定已搜索来源。powered、hot-pluggable 与 hitless 不得互换。
12. **公司—路线投影门**：`tools/research/check_company_route_projection.py` 要求 legal entity、product identity、route binding、maturity/event、支持边界和 unknown 显式化，并强制 `supply_claim: not_supported`。投影允许零个 `route_served_candidate`；机器不得为得到正例而放宽语义。
13. **候选可消费层门**：`tools/research/check_candidate_consumable_knowledge.py` 要求每条候选绑定原 source item、scope、禁止推论、challenge condition 与 review ceiling；稳定解释只有在晋升回执中解析为双 external pass 才能进入 `ready_for_user_decision`，公司路线观察必须保持 supply unsupported。
14. **晋升回执门**：`tools/research/check_promotion_receipt.py` 校验源批次与语义审计哈希、逐项决策、审阅连续性和 canonical effect；外部复核或用户批准缺一时不得出现 canonical application。
15. **动态网页语义快照门**：`web-semantic-snapshot-contract-v1.yaml` 要求同时冻结 raw response 与 normalized semantic object。首次动态页基线至少抓取三次；raw 漂移而 semantic 稳定只判为传输/渲染波动，semantic 漂移必须字段级 diff + 人工裁决。快照只改善可移植性，不自动提高 claim 证据等级。
16. **问题覆盖坐标门**：`expert-question-coverage-audit-v1.yaml` 要求现有 portfolio 中每条问题恰好映射一次，并分别标注物理格、路线轴和 WHY 阶段。空格是合法结果；覆盖盲区只有在去重、对象边界和 admission gate 均成立时才能形成未入队候选，不能自动创建正式 ID。
17. **正式写入目标门**：外审通过的研究治理规则不能因为 `格: []` 或随意附加 RB 而伪装成领域知识。`tools/research/check_knowledge_append_candidates.py` 要求候选显式选择物理知识目标、绑定 RQ/PQ、保持连续 KN 候选号、冻结 canonical 哈希、核验证据快照，并在临时副本中跑完整 `scan.py --check`；真实文件不允许被预检过程修改。
18. **依赖批与仓库总闸门**：依赖候选必须显式列出父批，检查器在临时副本中按父后子的顺序联合物化；该结果只证明候选内容可兼容 canonical schema。正式写入前还必须单独运行真实 workspace 的根目录白名单、pre-commit 与 `scan.py --check`；当前三者已恢复全绿，但每次拟写入仍需重新验证。
