# 出货量推断层（shipments.csv）：带推导链的推断行，等级封顶 C，双锚发布闸 + 校准列

**Status**: accepted（2026-08-08，grill-with-docs 五题裁决后由用户拍板）

账本要在"谁具备做各环节的能力"（points.csv，二值能力点）之上新增一个量化推断层：从产能信息+下游需求推断相关公司的**出货量**（实际交付只数）。决定：推断行独立成表 `shipments.csv`，主方程自下而上（营收 ÷ 型号矩阵加权 ASP），海关物质流做上限检、产能规划只做天顶检，证据等级封顶 C，FCC 封禁等未落地规则只进 D 级情景行、永不进基准表；发布前过双锚互锁（估计值与海关上限矛盾 >±30% 记"待核"不入表），行上预留校准列随新财报/新海关月报回算。

## 为什么是这个形状（关键取舍）

- **推断≠事实，必须自带推导链**。账本全部信用来自"每条结论可点回一手锚"。推断行若无推导式+输入锚，就是混入事实层的观点——所以每行必填推导式、收入输入锚、ASP 输入锚、两道检查锚。等级封顶 C 沿用解匿判例库"C 不承重"先例。**例外（2026-08-10 codex 验收对齐）**：年报产销表"量价齐露"属直接披露，可标 B（单一硬证据）；"推断不进 A/B"只约束推断行。
- **自下而上为主方程**。输入（公司营收、型号结构）全是一手锚；自上而下（海关×份额）的份额本身就是待推断对象，循环论证，只能当检查不能当产物；产能×利用率无锚可用，永不单独成方程（旭创"产能利用率充足"这类叙述不构成数）。
- **禁用单值 ASP**。旭创投关表自述"1.6T ASP 远高于市场传言"——混型号必须按 ASP 型号矩阵加权；T3 市场 ASP 一律进 macro_evidence 带 C 级注记，且拖整行到 C。
- **情景行与基准分离**。FCC 研究笔记（refs/us-china-optical-transceiver-restrictions.md）自身结论即"冻结新型号+存量豁免模板、规则未落地"——把未落地规则写成基准事实违背锚纪律；情景行（D 级）保留其前瞻价值：直美流收缩、东南亚/墨西哥承接、美厂受益。海关 2025→2026H1 目的地迁移（马来 34.6%→41.8%、直美 16.6%→6.9%）已是前兆信号。
- **校准列防腐化**。推断层最大的失败模式是"推断进去就变事实"。校准列（实际值/误差/校准日期）让推断随披露落地自动老去，接日更与半年报季节奏。

## Considered Options（落选者备忘）

- 塞进 macro_evidence.csv：该表装宏观结论不装公司级推导，且推导式无处放。
- 只写 knowledge.yaml 叙事：机器不可聚合查询，推断变散文即死亡。
- 只发布闸不回溯：入口管住了，衰老没人管，反对。
- 人工定期复核：不可靠机制（靠自觉），反对。
