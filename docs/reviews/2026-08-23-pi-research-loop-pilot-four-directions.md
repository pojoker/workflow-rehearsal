# Pi 研究循环小样与四个可行方向（待外部审核）

日期：2026-08-23
状态：审核草案，不是 canonical，不得据此直接改写 `knowledge.yaml` 或 `research_questions.yaml`

## 1. 本文要审核什么

拟议循环是：

1. 从 `out/研究问题树.md` 选择一个 `[待研究]` 问题；
2. 由 Pi 查找一手资料，起草答案和 append-ready YAML；
3. 根据答案暴露出的证据矛盾、定义空白或因果缺口，提出更细问题；
4. 独立审核后，把合格答案写入 `knowledge.yaml`，把真正必要的子问题提升到
   `research_questions.yaml`；
5. 重渲问题树，继续下一轮。

方向正确，但只能采用“**证据驱动、人工过闸、有限生长**”版本。不能让 Pi 根据自己的答案
自动生题并直接写入 canonical，否则模型推论会在循环中逐轮固化。

### 2.3 已核实的取证能力

Pi 确实找到了可追溯的一手材料。抽查结果：

- 中际旭创年报原文存在“光模块的作用就是光电转换”；
- 长芯博创年报原文存在“由光电子器件和功能电路等组成”；
- 源杰科技年报原文存在“光芯片加工封装为光发射组件（TOSA）及光接收组件（ROSA）”；
- 腾景科技年报原文存在“光模块又由光学元组件、光纤器件封装而成”；
- 汇绿生态年报原文存在 AOC “替代‘光模块+光纤’的分离方案”的表述；
- [OSFP MSA 官方页面](https://osfpmsa.org/)确实说明其规范覆盖机械模块、笼子、电接口和
  pinout，并给出 1U 36 个 OSFP 端口的说法；
- [IEEE P802.3df objectives](https://www.ieee802.org/3/df/proj_doc/objectives_P802d3df_221117.pdf)
  确实列出 800Gb/s 下 2 米铜缆、50/100 米 MMF、500 米/2 公里 SMF 的目标；
- [IEEE P802.3bs objectives](https://www.ieee802.org/3/bs/Objectives_16_0317.pdf)
  确实列出 400Gb/s 的 500 米、2 公里、10 公里 SMF 和 100 米 MMF 目标；
- [OIF 400ZR 官方发布](https://www.oiforum.com/oif-publishes-implementation-agreement-for-400zr-coherent-optical-interface/)
  确实把 400ZR 描述为面向特定距离互操作的项目。

因此，“Pi 能否找到可用一手资料”的答案是肯定的。问题主要出在材料组合、因果解释和入库
粒度，而不在基本检索能力。

## 3. 小样暴露的外行错误

### 3.1 把标准目标写成物理极限

Pi 从 IEEE “800G 双轴铜缆至少 2 米”的项目目标，推出“铜的物理极限在 2 米以内，超过就
必须换光”。这个结论不成立。

标准目标只直接证明：该项目要支持某种介质和距离。它不直接证明物理极限，也不排除其他铜缆、
AEC、有源方案、不同损耗预算或未来标准。正确写法应是“在该标准目标定义的档位中，铜缆目标为
至少 2 米；更长距离目标由光 PMD 承担”。

### 3.2 把真实引语拼成未经证实的统一定义

公司报告从功能或 BOM 解释“光模块”，MSA 从机械与电接口定义某个可插拔形态。这些来源各自
真实，但“功能 + 构成 + MSA 形态 + 谱系四项全部满足，才算光模块”是 Pi 自己合成的判定法，
不是任何标准的正式定义。

该合成框架可以保留为“研究方法/工程判定框架”，不能标成“事实定义”。

### 3.3 一条 KN 承担太多主张

`KN008` 同时回答定义、BOM、可插拔形态、速率谱系、样机纪律和判定规则。一条证据被修订时，
整条 KN 都会不稳定，也难以判断它究竟覆盖 RQ000、PQ001、PQ004 还是 TQ005。

建议拆成原子条目：

1. 功能定义；
2. 构成定义；
3. 可插拔形态由 MSA 定义什么；
4. “家族不等于样机”的研究边界。

根问题页面可以聚合四条 KN，但 canonical 不应把它们焊成一个事实。

### 3.4 用 schema 合法性替代语义正确性

`KN010` 为满足“技术路线 KN 必须引用 RB”，选取 `RB001/RB006/RB011` 作为三个路线的代表行。
但这三个 RB 实际分别是主机电接口或线路侧信号等 BOM/架构条目，不等同于完整路线对象。

校验器允许引用，并不代表语义正确。后续应增加“路线画像 ID”或明确一条 KN 引用的是路线、
路线条目还是某个物理变化，避免为了过 schema 随便挑一个 RB。

### 3.5 混淆正交维度

“速率/距离 PMD、光源平台、DSP/LPO、电接口、OSFP/CPO”不是同一层级的路线选项。若把它们
平铺比较，就会再次出现“EML vs CPO”“DSP vs 硅光”这类错位比较。

新问题必须标明自己属于产品标准轴、电接口轴、光子平台轴还是封装架构轴。跨轴问题只能写成
“某个组合画像”，不能写成同层二选一。

### 3.6 从机械不兼容跳到公司能力群不成立

OSFP 与 OSFP-XD 机械不兼容，并不能推出“同一物理格里的公司不能同时服务两种路线”。上游
器件、材料和设备供应商完全可能同时具备两种形态所需能力。

CQ005 把端口机械兼容性直接连接到公司能力群，是典型的跨层因果跳跃。若要研究，应改成：

> 形态变化具体改变了哪些结构件、连接器、散热件、装配工序和验证要求？这些物理变化是否足以
> 改变能力匹配条件？

只有先证明物理变化，才可以讨论能力群是否变化。

### 3.7 细节有趣不等于值得成为主树节点

“1U 为什么是 36 个 OSFP 端口”可验证，但目前不阻塞根问题、样机 BOM 或路线比较。直接提升
为 canonical 会使问题树沿着容易搜索的营销数字发散，而不是沿研究依赖生长。

这类问题应先留在 KN 的“未决注记”或研究包中；只有当端口密度成为 TQ002/TQ008 的关键判据时
再提升。

### 3.8 环境约束未被代理遵守

Pi 返回“本机 Python 无 yaml 模块，无法运行校验”，说明它尝试或考虑了系统 Python，而没有遵守
项目的硬约束：

```text
/Users/jowang/miniconda3/bin/python3
```

所有 Pi 任务提示词应把该路径放进硬性执行约束；结果中出现“系统 Python 缺 yaml”应直接判为
流程违规，而不是项目阻塞。

## 4. 推荐的受控循环

```text
选择待研究问题
  ↓
冻结研究合同（边界、答案形态、允许来源、时间/来源预算）
  ↓
Pi 只读检索 → 证据包 + 原子主张 + KN/WHY 草案
  ↓
证据闸（原文、锚点、出处、时间、口径）
  ↓
推理闸（事实/公司口径/行业共识/工程推论/投资假设分层）
  ↓
候选子问题闸（必须由矛盾、证据空白或下游阻塞触发）
  ↓
人工批准后写入 knowledge.yaml / research_questions.yaml
  ↓
Miniconda 校验、重渲、进入下一轮
```

### 4.1 每轮硬限制

- 一轮只研究一个 canonical 问题；
- 最多 3 个一手来源族，必要时扩到 5 个；
- 最多提交 3 条原子 KN 草案；
- 最多提出 3 个子问题候选，不要求凑数；
- 5 分钟无完整结果则停止，缩小问题或提供指定来源；
- Pi 不得直接修改 canonical；
- 每条事实必须有逐字引语和可定位锚；
- 每个子问题必须写“触发证据、现有问题为何未覆盖、验收条件、停止条件”；
- 未通过审核的候选只留在研究包，不出现在读者问题树。

### 4.2 子问题升级条件

同时满足下列条件才提升进 `research_questions.yaml`：

1. 由已核证据中的矛盾、空白或下游阻塞触发，而非模型自由联想；
2. 不与现有问题重复；
3. 答案形态明确，例如判界表、映射表、因果链、组件差异表；
4. 有可执行验收条件；
5. 有停止条件，答案不会无限展开；
6. 对后续至少一个 canonical 问题有解锁价值。

否则作为 KN 内“未决注记”，不长成树节点。

## 5. 四个可行推进方向

四个方向不是互斥产品，可以按 A → B → C → D 逐级推进。审核人也可以批准其中一条先做。

### 方向 A：基础定义与边界层（低风险，建议先做）

**目标**：回答 RQ000、PQ001、PQ002、TQ001、TQ002，建立大家共同使用的对象边界和术语。

**典型问题**：

- 什么是光模块，哪些定义是功能口径、哪些是形态口径？
- 光模块与 AOC、光引擎、CPO、光器件、光纤如何判界？
- 电→光→电功能链与系统边界是什么？
- 为什么应用约束会导致多条路线？

**产物**：原子 KN、术语/边界表、相邻对象判别表。

**优点**：最快纠正“把样机当全体”“不同维度平铺”等外行错误，为后续所有研究提供统一语言。

**主要风险**：容易陷入定义争论。必须允许多个发布主体口径并存，并标注适用边界，不能强行合成
唯一“标准定义”。

**准入/验收**：每个核心对象至少有标准/MSA和产业主体两个来源域；事实定义与研究框架分开写。

### 方向 B：参考产品纵向解剖（中低风险，最容易形成有用知识）

**目标**：选一款真实存在、边界明确的产品，从 PQ003 纵向做到 PQ009。

**典型路径**：

```text
真实 datasheet/规格
→ 组件 BOM
→ 组件功能
→ 电/光/机械/热接口
→ 材料与结构
→ 制造/装配工序
→ 设备
→ 验证指标
```

**产物**：参考样机说明书、组件表、连接图、工序设备表、测试验收表，以及可追加物理 KN。

**优点**：研究边界清晰，最容易核证；能把抽象物理树变成一只真实“解剖样本”。

**主要风险**：把一个 800G EML 或其他样机外推成所有光模块。每条结论必须标记：
`样机事实 / 家族共性 / 典型实现 / 未证实推论`。

**准入/验收**：必须先冻结产品型号、速率、PMD、封装、距离、光纤和技术平台；没有真实产品资料
不能开工。

### 方向 C：路线画像与 Why 因果链（中高风险，最有战略价值）

**目标**：从 TQ004-TQ011 出发，比较同一应用约束下的完整路线组合，解释为什么这么选以及物理上
改变了什么。

**典型路径**：

```text
应用需求
→ 瓶颈
→ 正交轴组合（标准/电接口/光子平台/封装）
→ 路线画像
→ 组件/接口/工序/设备变化
→ 能力要求
→ 条件、取舍、替代方案
```

**产物**：路线画像、物理差异表和经过证据闸的 `why_links` 草案。

**优点**：真正连接“技术路线”和“物理产业链”，回答用户最关心的“为什么要这么做”。

**主要风险**：因果链最容易被模型补全。标准事实不能直接跳成工程必然，工程可行不能直接跳成
经济占优，更不能直接跳成公司受益。

**准入/验收**：每条 Why 至少包含条件、取舍、替代方案；Investment 层必须晚于
CommercialAdoption 和 Economics；比较对象必须是同一层级的完整路线画像。

### 方向 D：公司能力群与路线服务证据（高风险，应最后做）

**目标**：在路线物理变化和能力要求已经稳定后，回答 TQ012/TQ013：哪些公司只是能力匹配，
哪些公司有路线级直接证据。

**产物**：

- 候选能力群：路线所需物理格 × 已过闸能力点；
- 确认服务群：路线 KN + 真实 point 的直接闭合；
- 如涉及供货，只读已核 `edges.csv`，另行展示。

**优点**：最接近产业链与投资研究用途。

**主要风险**：最容易出现“会做某设备 = 服务某路线 = 给某客户供货 = 公司受益”的四连跳。

**准入/验收**：

- 没有路线级直接证据时确认服务群必须为空；
- 候选群必须逐字标注“能力匹配，不是采用/供货证据”；
- 技术成立、商业采用、经济价值和投资结论分层记录；
- 不允许用机械兼容性、同一物理格或营销关键词代替路线服务证据。

## 6. 推荐决策

建议批准一个两阶段试运行：

1. 先做方向 A 的 3 个节点：`RQ000`、`PQ001`、`TQ001`，但把本次 Pi 的 3 条大 KN 拆成原子 KN；
