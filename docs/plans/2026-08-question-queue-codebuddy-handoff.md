## 1. 产品判断

上游方案的核心架构成立：问题应当是 canonical 账本的确定性补集，不应再维护第二棵问题树。五类问题都能从现有数据派生，确定性 ID、自动销号、豁免租约和真零双通道也与项目纪律一致。

三段原始会话同时说明：完整研究愿景还包括 Function→Component、部件制造、装配箭头、设备映射、正交技术路线，以及 Physics/Engineering/Economics/Investment 分层。当前 canonical 尚不足以让这些问题自动出生和销号，所以 **v1 是运营欠账队列，不是完整研究问题树**。这项边界必须出现在渲染页，不得通过新增自由模板或临时 schema 擅自补齐。

此外，上游方案仍有几处会导致错误销号或实现分叉的缺口。本委托书把它们定版：

1. 人工裁决必须明确参与出队；否则 `questions_manual.csv` 只是无人消费的旁路数据。
2. 真零和豁免都必须到期复核；否则“今天没查到”会永久遮蔽未来披露。
3. QD 不允许走人工裁决旁路；它必须回写 `triage.csv` 的处置字段，避免双账本。
4. QC 必须在校准三字段全部齐全后才销号，不能只看校准日期。
5. QE 必须同时满足“验证状态在白名单”和“锚点非空”才销号。
6. 队列内排序、未知期间排序、页脚口径和 `--verify` 文件集合必须确定化。
7. 新增根目录 CSV 时必须同步 `scan.py` 不变量⑥的根目录白名单。
8. 输出必须声明 v1 覆盖边界，避免把五类维护欠账误读成全部研究问题。
9. 队列不是只读看板：每条问题必须显示 canonical 回填目标；QB 的研究交付物必须明确为可直接追加到 `knowledge.yaml` 的完整 KN YAML 补丁。

## 4. 数据与 ID 合同

### 4.1 派生问题的统一字段

内部可使用字典或轻量结构，但每条至少要有：

- `question_id`
- `kind`：QA/QB/QC/QD/QE
- `question`
- `acceptance_anchor`
- `source_ref`
- `writeback_target`
- `source_order`
- `sort_key`

ID 只按第一个连字符拆分前缀和来源 ID，避免 QD 的 `hit_id` 内含连字符时被破坏：

- `QA-{cell_id}`
- `QB-{cell_id}`
- `QC-{row_id}`
- `QD-{hit_id}`
- `QE-{edge_id}`

### 4.2 QA：空叶格

生成条件：`tree.yaml` 中的叶格没有任何 `points.csv` 行。

- 问题：`{格名}谁在做？`
- 验收：自家披露件或互动易/e互动回答引语 + 合法锚点
- 来源：`tree.yaml:{cell_id}`
- 回填目标：`points.csv`
- 自动销号：该格出现至少一个合法点

### 4.3 QB：有点但无知识覆盖

生成条件：叶格已有点，但没有任何 `knowledge.yaml` 条目的 `格` 列表包含该 `cell_id`。以 `knowledge.yaml` 的实际 `格` 列表为准，不要另从 `tree.yaml.knowledge_ids` 发明第二套覆盖口径。

- 问题：`{格名}是干嘛的、为什么难、怎么判断谁够格？`
- 验收：该格进入至少一条带合法类型化锚的 KN
- 来源：`tree.yaml:{cell_id}`
- 回填目标：`knowledge.yaml`；需要展示反向索引时，可选同步对应 `tree.yaml` 叶格的 `knowledge_ids`
- 自动销号：该格进入任一 KN 的 `格` 列表

QB 研究回答必须交付 append-ready YAML 条目，不能只交 prose。字段至少包括：

```yaml
- id: KN###
  格: [目标cell_id]
  标题: ...
  一句话: ...
  说细点: ...
  怎么用它判断: ...
  证据:
  - 谁: ...
    原话: ...
    出处: ...
    锚型: url|local_file|ledger_ref|search_protocol|web_snapshot
    锚: ...
  录入日期: 'YYYY-MM-DD'
```

这里的 `KN###` 只是格式占位，作答时必须读取当时 `knowledge.yaml`，按最大现有 KN 顺延。
这段条目追加到顶层 `knowledge:` 列表后须通过不变量⑧。QB 是否销号只看
`knowledge.yaml` 的实际 `格` 列表，不以 `tree.yaml.knowledge_ids` 为第二口径。

### 4.4 QC：到期应校准的 C 级基准行

生成条件必须同时满足：

1. `证据等级 == "C"`
2. `情景标记 == "base"`（精确匹配）
3. `校准实际值`、`误差`、`校准日期`没有全部齐全
4. 期间已经解锁

期间解锁：

- `YYYY年度`：`YYYY+1-05-01`
- 以 `YYYYH1` 开头：`YYYY-09-01`
- 无法解析：fail-open，仍生成问题；排序放在所有可解析期间之后

- 问题：`{公司}{期间}推断值该回算了吗？`
- 验收：`校准实际值`、`误差`、`校准日期`三字段全部非空，其中校准日期是合法 `YYYY-MM-DD`
- 来源：`shipments.csv:{row_id}`
- 回填目标：`shipments.csv`
- 自动销号：仅在上述三字段全部齐全时销号

不要把历史 B/D 行对校准列的误用扩大成本轮清洗任务；新增校验只需确保 C+base 候选不会因单填日期而静默销号。

### 4.5 QD：待判召回

生成条件：`triage.csv` 的 `处置 == "待判"`。

- 问题：`{公司}+{格}判不判？`
- 验收：`triage.csv` 处置变为当前合法枚举中的非“待判”值
- 来源：`triage.csv:{hit_id}`
- 回填目标：`triage.csv`
- 自动销号：处置不再是“待判”

QD 不允许写入 `questions_manual.csv`。不存在“豁免一个待判行”或“在第二张表里把待判记成真零”的旁路。

### 4.6 QE：未完成原文核验的边

只有同时满足以下两项才视为已核并销号：

1. `验证状态` 与下方白名单中的某个值逐字相等
2. `锚点` 非空

否则生成：

- 问题：`{供方}→{需方}这条边核过原文吗？`
- 验收：验证状态进入白名单且锚点非空
- 来源：`edges.csv:{edge_id}`
- 回填目标：`edges.csv`

白名单冻结为当前 17 个逐字值：

## 5. 排序合同

全局类型顺序固定：

```
QD → QA → QB → QC → QE
```

类型内顺序：

- QD：`triage.csv` 原始行序
- QA：非“共用”路线优先，然后按 `tree.yaml` 深度优先遍历中的叶格顺序
- QB：按 `tree.yaml` 深度优先遍历中的叶格顺序
- QC：可解析期间按解锁日从早到晚，再按 `shipments.csv` 原始行序；不可解析期间放在可解析期间之后并保持原始行序
- QE：`edges.csv` 原始行序

不得依赖集合迭代顺序，也不要按含数字的 ID 做容易出错的字符串重排。

## 6. 人工裁决合同

新建 UTF-8 CSV，表头逐字为：

```csv
question_id,处置,理由,验收锚型,双通道记录,复核日期,会话日期
```

初始文件只有表头。

### 6.1 有效裁决

- `处置` 只能是 `豁免` 或 `真零`。
- QA/QB/QC/QE 可裁决；QD 禁止裁决。
- 同一 `question_id` 只能有一行。
- `理由`、`验收锚型`、`复核日期`、`会话日期` 必填。
- 两个日期必须是 `YYYY-MM-DD`；`会话日期 <= 今天 < 复核日期`。
- 日期等于今天视为到期：该问题立即重开，`scan.py --check` 报错。
- 有效且未到期的裁决从可见队列中移除。
- `真零` 还必须通过双通道结构校验；`豁免` 的 `双通道记录` 必须为空。

真零格式逐字为：

```text
通道A{关键词=..;语料范围=..;检索日期=..;命中数=..}|通道B{关键词=..;语料范围=..;检索日期=..;命中数=..}
```

校验要求：

- 必须整串匹配，A/B 各四键且值非空，不能只做 `in` 子串检查。
- 两个通道内的 `检索日期` 均为合法日期，且不晚于 `会话日期`。
- A/B 的 `语料范围` 不能逐字相同，防止复制同一通道冒充双通道。

### 6.2 裁决与派生的合并顺序

1. 先生成完整 raw derived set。
2. 再读取并验证人工裁决。
3. 有效、未到期且仍指向 raw derived question 的裁决负责 suppress。
4. 到期或无效裁决不 suppress，问题重回可见队列。
5. 裁决引用的来源 ID 仍存在、但对应问题已经不再派生，记为“待清理裁决”。
6. 裁决引用的来源 ID 本身不存在，由不变量⑬报错，不归为“待清理”。

真零/豁免只是有期限的例外，不改 canonical 数据；一旦 canonical 数据补齐导致问题天然销号，人工行就成为待清理项。
