# 出货量层可视化 · 设计说明（2026-08-23）

> 读者：workbuddy（负责网页设计）。本文件是需求说明，不是设计稿。
> 数据契约以 CSV 为准；本文件不改数据、不建页面。页面上的每个数字都必须能回溯到 CSV 的一行。

## 1. 这是什么

把 `shipments.csv`（出货量推断层）第一次变成人能看的界面。它回答一个问题：**各环节、各公司，真实出货了多少只/颗/台**——不多回答任何别的。

## 2. 数据源（只读）

| 文件 | 内容 | 规模（2026-08-23） |
|---|---|---|
| `shipments.csv` | 出货量事实与推断 | 103 行 = 2025 年 36 + 2024 年 34 + 2023 年 32 + 情景 1 |
| `company_segment_revenue.csv` | 分部收入事实（金额） | 13 行（可选联动；与出货量机器可分，不混排） |

`shipments.csv` 21 个字段：`row_id / 公司 / cell_id / 期间 / 出货量 / 单位 / 推导式 / 收入输入 / 收入锚 / ASP输入 / ASP锚 / 海关上限检 / 海关锚 / 产能天顶检 / 产能锚 / 证据等级 / 情景标记 / 校准实际值 / 误差 / 校准日期 / 检索日期`。

覆盖六层：模块（MOD）、芯片（C）、器件（D）、结构件（B）、设备（EQ）、材料（M），35+ 家公司。

## 3. 口径铁律（页面必须让读者看出来）

1. **证据等级三色**：B=年报产销表直接披露；C=推断（有完整推导链）；D=情景（未落地政策假设）。等级是每行的一等公民，不是脚注。
2. **聚合口径不是单格**：很多行的 `cell_id` 是聚合口径（如"光器件""行业大类"，字段内含"聚合"字样）。这些行**不得**画进单一环节的柱状图，只能以"公司级/行业级"身份出现。
3. **ASP 是隐含混合口径**：`ASP输入` 由收入÷出货量反算，混型号、混速率。**禁止**画成型号级价格曲线或解读为"800G 单价"。
4. **情景行物理隔离**：D 级情景行（FCC 相关）在视觉上必须与基准行分区（独立区域+明显标识），不得混进时间序列。
5. **校准列大多为空是诚实状态**：`校准实际值/误差/校准日期` 目前只回填了 1 行——这不是 bug，是校准机制还没跑。页面应显示"待校准"，不要隐藏这三列。
6. **单位混杂**：只/颗/件/支/片/台/台套/千克/万平方米/千只等。跨公司加总没有任何意义，页面不提供"合计"。

## 4. 建议的页面区块

- **层×公司矩阵**：六层为纵轴，公司为行，2023→2025 三期出货量为主格内容；空格显示"无披露"而非 0。
- **公司详情卡**：点开一行展开五锚——推导式、收入输入+锚、ASP 输入+锚、海关上限检+锚、产能天顶检+锚。锚是可点开的链接。这是本产品区别于一切第三方数据页的地方：**每个数字都能当场验算**。
- **校准区**：已回填行显示 推断值 vs 实际值 vs 误差；未回填行显示"待校准（下一窗口：2026 半年报季）"。
- **情景隔离区**：D 级行单独成区，标题注明"未落地规则的情景假设，不是事实"。

## 5. 禁区（与全项目一致）

- 不画"A 是 B 的供应商"任何连线或暗示（项目全局不做无双边实证的供货关系）。
- 不做投资价值判断、不给排名解读。
- 不把"没有数据"渲染成"落后"。
- 不改 CSV 本身；页面是渲染产物，数据只有一个真源。

## 6. 工程边界

- 视觉语言与 `out/全景.html`、`out/参与识别.html` 保持一致（卡片、四态结论色、锚点可点）。
- 若落地进 WorkBuddy 合并页：生成器是 `build_detailed_capability_report.py`，该文件当前是 codex 车道（协作账本占用中），接线需先在账本登记。
- 若独立成页：新增渲染器放主树，走 scan/render/participation 钩子。

## 7. 验收清单（可机检）

- 页面行数与 `shipments.csv` 一致（103）；等级 B/C/D 配色可区分；情景行不在基准区。
- 聚合口径行带"聚合口径"标识且不进单格图。
- 任一数字 hover/点开后能看到该行五锚原文与链接。
- 校准列为空的行显示"待校准"，不显示 0。
