# PROJECT_CHARTER — 光模块领域研究系统

> 会话入口顺序：`AGENTS.md` → 本文件 → `docs/control/ACTIVE_WORKPACK.yaml`。
> 本文件定义**边界与判据**，不定义任何一轮具体任务；具体任务只在工作包里。

## 1. 北极星

维护**单一、可审计的光模块领域研究系统**：

1. 回答真实的领域问题（不是回答自造的流程问题）；
2. 保持证据边界（事实 / 派生 / 候选 / UNKNOWN 分列，不互相冒充）；
3. 区分**事实**（有锚、可核验）、**派生**（从事实推出，须显式推导）、**候选**（待授权晋升）、
   **UNKNOWN**（明确不知道，不许用模糊措辞掩盖）；
4. 经人工复核的结论写入**唯一 canonical 数据源**。

## 2. 必须产出

- 读者可看到的领域回答：一个具体产品/接口/工艺链被讲清楚，读者能据此理解或判断。
- 每条结论带证据锚与类型，机器门（`scan.py --check` 等）可通过。
- 证据不足处显式标注 `UNKNOWN` 或 `blocked`，并说明缺什么。
- 结论进入 canonical 前，有明确的人工复核记录与用户授权。

## 3. 明确非目标

本仓库**不做**：

- 通用 Agent Control Plane、状态机、自动 close/reopen、回执（receipt）、清单（manifest）、
  快照血统（snapshot lineage）、取代（supersession）引擎、比较面。
- 产品登记表（product registry），以及自动生成的 `offers_product` / `implements_route` 主张。
- 脱离真实领域问题而存在的新关系类型、新顶层体系、新 schema。
- 为了"流程完整"而制造的中间产物：不为一个结论再造一套 preflight、receipt 或平行档案。
- 领域结论的自动化判定：机器只判结构与引用闭合，语义蕴含由人判。

## 4. 目标变更权限

- 只有**用户**可以改变北极星、工作包范围、允许写入路径和验收标准。
- 执行者可以**停止并升级**，可以提出建议，但**不得**自行改目标、自行扩范围、自行晋升结论。
- 用户未授权写入 canonical 时，正确产出是"候选 + 停止"，不是"先写入后补授权"。

## 5. 架构准入闸（新增任何架构前必须同时满足四条）

新增关系类型、顶层体系、schema、引擎、状态机、注册表等架构前，必须逐条给出证据：

| # | 闸 | 判据 |
|---|---|---|
| 1 | **两个真实切片被阻塞** | 举出**两个**已经真实发生、且**现有架构无法表达**的领域切片。一个切片不够，假设的切片不算。 |
| 2 | **生产数据在用** | 该架构要承载的字段已经出现在真实 canonical 数据里，不是为将来预留。 |
| 3 | **替代一个既存人工步骤或实现** | 明确说明它替换掉哪个现在靠人记、人做或已有代码做的东西；只是"多一种表达"不通过。 |
| 4 | **读者可见结论所必需** | 缺了它，某个读者可见的结论就无法成立或无法表达；只便利后台整理不通过。 |

四条**全部**满足才提交给用户裁决；任一条不满足 → 不实现，写入 `docs/control/PARKING_LOT.md`。

## 6. 停止 / 升级条件

出现下列任一情况，停止当前动作并向用户报告，不自行处置：

- 需要回答的问题不在工作包内；
- 需要的写入路径不在允许列表内；
- 需要通过第 5 节准入闸的架构变更；
- 需要读取第 2 节禁读材料才能继续；
- 证据不足但结论"看起来很清楚"；
- 用户指令与本宪章或工作包冲突。
