# 光模块供应链参与识别 MVP

## 1. 产品概览

- 阶段：内部可用 MVP
- 目标用户：研究员（维护与判定）、读者（检索结论与证据）
- 要解决的问题：在给定公司宇宙内，判断一家公司是否有可追溯证据表明其参与光模块供应链。

## 2. 目标与范围

### 本轮目标

输出一张公司级名单，每家公司只有一个当前结论，并能回到披露原文：

1. **已确认参与**：存在“生产中”的过闸点。
2. **待确认**：仅有在建/送样等未量产点，或仍有人工待判线索。
3. **尚未发现已过闸证据**：年报已纳入，但当前没有过闸点或待判线索。
4. **未覆盖**：公司在宇宙内，但年报语料尚未到位。

“尚未发现已过闸证据”不是“确认不参与”。

### 纳入边界

- 材料：衬底、外延、特气/MO 源/耗材、高速板材。
- 芯片：激光器、探测器、硅光 PIC、DSP/Driver/TIA/CDR/MCU。
- 器件：TOSA/ROSA/BOSA、AWG、隔离器、滤光片、透镜、FAU/MPO。
- 电路与结构：PCB、陶瓷管壳、壳体、散热。
- 制造：光引擎、模块组装、EMS、封装测试。
- 设备：外延、光刻/刻蚀、固晶、耦合、键合、AOI、测试和气密封装设备。

### 非目标

- 不在本轮证明客户—供应商关系。
- 不估算收入、订单和市场份额。
- 不把交换机、服务器、运营商等下游使用者自动算作供应链参与者。
- 不因关键词缺席直接下“确认不参与”结论。

### 成功标准

- `corpus/_frozen.csv` 每个唯一代码在名单中恰好一行。
- 每个“已确认参与”结论至少有一条 `points.csv` 证据。
- 页面可搜索、可按结论过滤，且证据链接在有 URL 时可点击。
- 生成过程只依赖 Python 标准库，结果可重复验证。

## 3. 角色

### 研究员

- 维护公司宇宙和年报语料。
- 复核关键词上下文，判定参与、待确认或驳回。
- 只有研究员可以修改 `points.csv` 和 `triage.csv`。

### 读者

- 搜索公司、查看当前结论、环节和证据。
- 不在展示页直接修改判定。

### 系统

- 批量召回候选。
- 聚合公司级状态。
- 检查覆盖分母、状态与证据闭合。

## 4. 核心流程

1. 年报进入 `corpus/annual/<代码>/`，公司进入 `_frozen.csv`。
2. `scan.py` 使用行业词表召回上下文；`ANY` 表示只做参与识别、不预判产业链格子。
3. 研究员将候选写入 `triage.csv`，必要时将过闸事实写入 `points.csv`。
4. `participation.py` 聚合同一公司的全部点和候选，生成公司级名单。
5. 读者在 HTML 中搜索、过滤并查看证据。

终点是“每个公司都有当前状态”，不是“每个公司都有肯定或否定答案”。

## 5. 数据来源与字段

| 来源 | 用途 | 关键字段 |
|---|---|---|
| `corpus/_frozen.csv` | 公司宇宙与分母 | 代码、名称、市场、行业分类 |
| `corpus/annual/` | 年报覆盖状态 | 代码目录是否存在 |
| `points.csv` | 已过闸参与事实 | 公司、cell_id、状态、引语、锚点URL、日期 |
| `triage.csv` | 待判候选 | 公司、cell_id、处置、摘要、日期 |
| `words.txt` | 关键词召回 | 词、cell_id、排除词、上下文 |

公司级输出字段：

`代码、公司、市场、行业分类、年报覆盖、结论、参与环节、证据状态、关键原文、锚点、数据日期`

## 6. 系统流与模块

`公司宇宙 → 年报语料 → 关键词召回 → 人工判定 → 事实点/待判 → 公司级聚合 → CSV/Markdown/HTML`

- `scan.py`：候选召回，不做最终事实判断。
- `points.csv` / `triage.csv`：人工判定账本。
- `participation.py`：公司级状态聚合、输出和一致性检查。
- `out/参与识别.*`：读者侧产物。

## 7. 状态转换

- 未覆盖 → 尚未发现：年报目录到位，但没有过闸或待判证据。
- 尚未发现 → 待确认：出现尚未处理完成的候选，或只有在建类点。
- 待确认 → 已确认参与：至少一个“生产中”点过闸。
- 任意状态可因语料更新和人工复核重新计算，不手改展示结果。

优先级：`已确认参与 > 待确认 > 尚未发现已过闸证据 > 未覆盖`。

## 8. 非功能要求

- 可追溯：确认结论必须回到 `points.csv`。
- 可重复：同一输入生成字节一致的输出。
- 诚实边界：无证据不写“否”，非 URL 锚点按文本显示。
- 轻依赖：参与识别生成器不依赖 YAML 和关系边。

## 9. 验收、风险与交接

### 验收

- 运行 `python3 participation.py` 成功生成三种格式。
- 运行 `python3 participation.py --check` 返回全绿。
- HTML 首屏显示覆盖和结论统计；搜索与筛选可用。
- “已确认参与”行不允许缺少关键原文。

### 风险

- 子公司披露与上市公司主体需要别名/母子关系归并。
- 年报的关键词缺席不能证明业务不存在。
- 研发、送样、客户验证与量产边界仍需要人工判断。
- 泛词（如“光通信”）召回率高但误报也高。

### 开发交接

先稳定公司级判断，再逐步补别名登记和词表；关系边、市场规模和漂亮的全景图均保持为可选扩展，不得阻塞名单更新。

# v2 方向草稿：动态发现与分层证据

状态：方向草稿，尚未进入开发  
日期：2026-07-26  
承接：保留当前公司级参与名单，引入跨行业动态发现，并将参与事实与供货关系分闸。

## 1. 产品概览

### 产品定位

建立一个可持续更新、可追溯的光模块供应链参与识别系统，分别回答：

1. 哪些公司可能参与光模块供应链？
2. 公司具体做什么、处于哪个环节？
3. 是否存在证据证明其已经实际供货？
4. 该事实或关系是研发中、当前有效、历史发生，还是仍待确认？

当前阶段仍为研究型 MVP。本轮不恢复旧版完整关系图谱，而是在现有公司级名单上补回已经验证有效的跨行业发现能力。

### 核心问题

当前版本以四个申万行业构建基础公司池，再扫描池内年报。该方法可以稳定回答“给定公司池内是否参与”，但存在以下边界：

- 供应链跨越机械设备、电子化学品、有色金属、汽车零部件等证券行业分类；
- 池外公司不会被当前扫描程序主动发现；
- 公司披露产品用于光模块，只能证明参与，不能直接证明客户—供应商关系；
- 招股书供应商反查、旧证据迁移和人工线索尚未形成统一的数据入口。

## 2. 目标与范围

### 本轮目标

- 将公司池从固定行业分母改为可记录纳入路径的动态候选宇宙；
- 恢复客户侧招股书、问询回复和采购披露的实名供应商反查；
- 使用跨行业年报扫描补漏，而不是将行业分类视为供应链边界；
- 将“候选”“确认参与”“确认供货”拆成独立证据层级；
- 保留当前公司级名单作为主要读者产品；
- 只为有合格关系证据的公司建立供货关系，不要求所有参与公司都有关系边。

### 非目标

- 不承诺一次性查全全市场供应商；
- 不因关键词缺席认定公司没有参与；
- 不把研报、媒体、产业链图或付费数据库条目直接作为确认依据；
- 不估算收入、订单、市场份额、业绩弹性或投资价值；
- 不恢复旧版海关、关系时序、双侧金额指纹等全部复杂模块；
- 不要求第一阶段立即下载并处理全部 A 股年报。

### 成功标准

- 罗博特科、南大光电、斯瑞新材等跨行业案例可以通过机制进入候选池，而非人工硬编码；
- 徕木股份等仅有开发证据的公司不会被展示为已确认真实供应商；
- 每个“确认参与”结论都有产品、应用、阶段和一手证据锚点；
- 每个“确认供货”结论都有供需双方、产品、时间和关系证据；
- 输出只报告已定义语料范围内的覆盖率，不使用“全市场查全率”表述；
- 同一输入可以重复生成一致结果。

## 3. 用户角色

### 研究员

职责：

- 维护种子公司、动态候选宇宙和文件语料；
- 复核扫描命中上下文；
- 判定候选是否通过参与闸和供货闸；
- 处理公司、子公司、收购标的、别名和更名；
- 修复失效或错误证据锚点。

权限：

- 可以修改候选、事实点、关系和实体登记；
- 不直接修改渲染输出；
- 不得将 T2/T3 线索直接升格为确认结论。

### 读者

职责：

- 搜索公司；
- 查看公司做什么、证据阶段和证据原文；
- 区分产业链参与与实际供货；
- 沿锚点回到原始披露。

权限：

- 只读；
- 不在展示层修改判定。

### 系统

职责：

- 获取和登记披露文件；
- 从客户侧文件抽取实名供应商候选；
- 扫描跨行业年报的组合关键词；
- 聚合公司级参与状态和关系状态；
- 校验分母、实体映射、状态闭合、证据锚点和输出幂等。

## 4. 核心工作流

### 工作流 A：客户侧供应商反查

触发条件：

- 新增核心光模块、光芯片或光器件公司；
- 新招股书、问询回复、重大合同或年度报告到位；
- 现有供应链环节出现缺口。

流程：

1. 从核心公司披露中定位前五大供应商、采购产品、委托加工、关联采购和重大合同章节；
2. 提取对手方名称、产品、期间、金额或占比、披露方、原文和 URL；
3. 进行实体归一，识别上市公司、子公司、未上市公司和贸易通道；
4. 将新主体写入动态候选宇宙，记录纳入路径为“客户侧反查”；
5. 客户侧实名采购事实进入供货闸；
6. 对公开公司补取自身披露，验证其产品和产业链位置。

结果：

- 产生高精度跨行业候选；
- 在字段完整时产生客户—供应商关系候选；
- 未上市供应商保留为观察主体，不强行映射至上市公司。

结束条件：

- 每条抽取记录完成实体处置和证据判定，或明确进入待判队列。

### 工作流 B：跨行业年报扫描

触发条件：

- 年度报告快照更新；
- BOM 词表更新；
- 客户侧反查发现新的产品同义词；
- 某供应链环节缺少候选。

扫描顺序：

1. 机械设备；
2. 电子化学品；
3. 有色金属；
4. 汽车零部件；
5. 基础化工；
6. 其他电子、材料及精密制造行业；
7. 有明确收益后再扩展至全 A 股。

组合词示例：

- `光模块 + 壳体/热沉/连接器/PCB`
- `硅光/CPO + 耦合/键合/封装/测试`
- `光芯片/InP + 磷烷/MO源/靶材/衬底`
- `800G/1.6T + 量产/出货/客户验证`

流程：

1. 扫描年报并保存命中上下文；
2. 过滤定义句、行业背景、募投愿景和非本业务碰撞；
3. 将有效命中写入候选队列；
4. 人工判断产品、应用和阶段；
5. 通过参与闸后写入公司事实点；
6. 若没有客户侧或合同侧证据，保持“确认参与/待供货验证”。

结束条件：

- 所有命中均有待判、驳回或入点处置，不允许候选静默消失。

### 工作流 C：读者查询

触发条件：

- 读者搜索公司或供应链环节。

流程：

1. 系统返回公司级参与状态；
2. 展示具体产品、产业链位置、阶段和原文；
3. 单独展示是否存在已确认供货关系；
4. 展示披露侧、证据类型、报告期和锚点；
5. 对历史关系、待确认和证据过期给出明确标记。

结束条件：

- 读者可以区分“相关”“参与”“实际供货”，并能回到原始披露复核。

## 5. 证据分层与判定闸

### 信源等级

| 等级 | 来源 | 用途 |
|---|---|---|
| T1 | 交易所、巨潮、SEC、公司官方公告、招股书、问询回复、合同 | 确认参与或确认供货 |
| T2 | 权威媒体、行业媒体、正式采访 | 发现候选、定位 T1 |
| T3 | 研报、产业链图、iFind、公众号、搜索摘要 | 仅发现候选 |

T2、T3 不得直接产生确认结论。

### 第一闸：候选闸

通过条件：

- 存在与光模块 BOM、光芯片、光器件或制造工序相关的具体线索；
- 线索包含可继续追查的公司、产品或披露文件。

输出：

- 候选公司；
- 待验证产品；
- 线索来源；
- 待查 T1 路径。

### 第二闸：参与闸

通过条件：

- T1 披露明确主体；
- 明确具体产品或设备；
- 明确光模块、光芯片、光器件或对应制造工序的应用；
- 能判断研发、送样、验证、小批量、批量供应或生产中等阶段；
- 有原文、URL、报告期和检索日期。

通过参与闸不等于确认客户—供应商关系。

### 第三闸：供货闸

通过条件至少满足一种：

- 客户侧招股书或公告实名披露采购；
- 实名合同、订单、中标或采购文件；
- 供应方一手披露明确客户、产品和供货阶段；
- 双侧一手披露可以闭合为同一关系。

关系字段必须包含：

- 供方；
- 需方；
- 产品；
- 期间；
- 关系类型；
- 披露方；
- 原文；
- URL；
- 关系状态。

## 6. 数据来源与数据血缘

### 外部数据源

| 数据源 | 内容 | 获取方式 | 证据用途 |
|---|---|---|---|
| 巨潮资讯 WebAPI | 公司、市场、行业分类 | API | 候选宇宙元数据 |
| 巨潮/交易所披露 | 年报、公告、问询回复、投资者关系记录 | PDF/HTML | 参与与关系 T1 |
| 上交所/深交所招股书 | 客户、供应商、采购产品、金额和占比 | PDF | 客户侧反查 T1 |
| SEC EDGAR | 美股 10-K/8-K | HTML/PDF | 境外公司参与或关系 T1 |
| 公司官网 | 产品、产能、客户或合同公告 | HTML/PDF | 补充 T1 |
| 媒体、研报、付费库 | 公司和事件线索 | 人工或接口 | 仅候选发现 |

### 内部数据血缘

`原始披露文件 → 文件登记 → 命中/抽取记录 → 候选处置 → 参与事实点 → 供货关系 → 公司级聚合 → 读者输出`

任何展示结论都必须能够沿该链条回到原始文件。

## 8. 端到端系统流

`种子公司/缺口 → 客户侧反查 + 跨行业扫描 → 动态候选宇宙 → 实体归一 → 候选闸 → 参与闸 → 公司事实点 → 供货闸 → 关系事实 → 公司级聚合 → 名单/关系表/PDF`

两条发现路径共享同一候选队列、实体登记和判定闸，避免各自形成不可追溯的人工补丁。

## 9. 功能模块

### 语料与文件模块

- 维护文件元数据；
- 下载、去重和解析披露文件；
- 标记缺失、损坏和解析失败。

### 客户侧反查模块

- 定位供应商、客户、委托加工和重大合同章节；
- 抽取对手方、产品、期间、金额、占比和原文；
- 生成关系候选。

### 跨行业扫描模块

- 管理 BOM 词表和组合词；
- 扫描指定行业或全市场语料；
- 保存上下文和排除原因；
- 输出候选而非直接判定。

### 实体登记模块

- 处理法人、集团、子公司、品牌、收购标的和更名；
- 保留实体映射证据；
- 禁止仅凭名称相似自动合并。

### 判定闸模块

- 管理候选、参与和供货三个层级；
- 强制记录判定人、日期、理由和证据；
- 支持驳回、重开和证据过期。

### 聚合与输出模块

- 生成公司级参与名单；
- 单独生成已确认供货关系表；
- 展示语料边界、覆盖范围和证据等级；
- 生成 CSV、HTML、Markdown 和 PDF。

## 10. 状态设计

### 候选状态

`新发现 → 待判 → 驳回 / 进入参与核验`

### 参与状态

`待核验 → 研发中 → 送样/验证 → 小批量 → 批量/生产中 → 历史/失效`

公司级展示：

- 确认参与；
- 待确认；
- 尚未发现已过闸证据；
- 未覆盖。

### 供货关系状态

`待关系证据 → 已确认历史供货 / 已确认当前供货 / 匿名半边 / 无法闭合 / 已失效`

公司级参与状态和关系状态分别计算，不互相覆盖。

## 11. 非功能要求

- 可追溯：所有确认结论必须具备原文和有效 URL；
- 可重复：相同语料、词表和判定账本生成一致结果；
- 可审计：驳回、重开、降级和失效均保留记录；
- 有界完整：覆盖率必须绑定语料范围、文件类型、报告期和词表版本；
- 实体安全：子公司和上市公司归并必须有证据；
- 幂等：重复获取文件和重复运行扫描不产生重复候选；
- 性能：扫描和校验采用脚本批量完成，人工只用于判定闸。

## 12. 验收标准

### 数据验收

- 动态候选宇宙的每家公司都有纳入路径；
- 每份参与计算的披露文件都有文件登记；
- 每个确认参与点都有产品、应用、阶段、原文和 T1 URL；
- 每条确认供货关系都有供需双方、产品、期间和关系证据；
- 文本型“有锚”“同上”不得作为最终读者锚点；
- 待判候选数量、来源和老化时间可统计。

### 场景验收

- 南大光电可由源杰科技供应商表反查发现；
- 深圳宏钢可由长光华芯供应商表反查发现；
- 罗博特科可由硅光/CPO 设备组合词发现并通过参与闸；
- 斯瑞新材可由光模块壳体组合词发现并标记批量阶段；
- 徕木股份在缺少供货证据时不得进入确认供货列表；
- 泛行业背景描述、定义句和研发愿景能够被驳回或降为待确认。

### 输出验收

- 公司参与名单和真实供货关系列表分开；
- 页面明确展示当前语料边界；
- 每条结论可以回到原始披露；
- `participation.py --check` 及新增数据质量检查全部通过。

## 13. 风险与开放问题

### 风险

- 全市场年报扫描可能产生大量泛词误报；
- 年报很少实名披露供应商，单靠年报无法完成真实关系验证；
- 招股书供应关系可能是历史关系，不能自动视为当前有效；
- 未上市公司和贸易商可能无法映射到上市公司；
- 同一产品可能服务多个行业，通用材料不能仅凭产品能力纳入；
- 现有文本型锚点需要补链，否则无法满足最终可追溯要求。

### 开放问题

- “当前供货”的有效期默认按一年、两年还是最后一次公开观察定义；
- 互动易是否只作为线索，还是在明确主体和产品时允许进入参与闸；
- 全 A 股年报扫描的启动阈值和存储预算；
- 未上市供应商是否进入读者名单，还是仅在关系表中展示；
- 客户侧实名采购是否可以单独确认供货，还是要求供应方再次核验。

## 14. 开发交接

### 建议实施顺序

第一阶段：修复当前证据基础。

- 修复徕木股份错误锚点；
- 将文本型锚点补成正式 URL；
- 给现有事实点补“参与证据/供货证据”分类；
- 增加文件登记和纳入路径字段。

第二阶段：恢复已验证的客户侧反查。

- 以源杰科技、仕佳光子、长光华芯三份招股书为回归样本；
- 将既有抽取结果迁入统一候选队列；
- 验证实体归一和供货闸。

第三阶段：跨行业扫描试点。

- 先覆盖机械设备、电子化学品、有色金属和汽车零部件；
- 采用组合词而非单个泛词；
- 统计命中数、驳回率、净新增参与公司和净新增供货关系。

第四阶段：扩容决策。

- 根据试点收益决定是否扩至其他行业或全 A 股；
- 不以下载文件数量为成功指标；
- 只有候选净新增率和证据过闸率达到预设阈值才扩大语料。

### 实现注意

- 先改数据结构和校验器，再改页面；
- 发现脚本不得直接写入确认事实；
- 不将旧 `edges.csv` 全量恢复为当前产品依赖；
- 旧证据迁移必须重新补文件级锚点；
- 每次扩容都冻结语料范围、词表版本和判定快照。
