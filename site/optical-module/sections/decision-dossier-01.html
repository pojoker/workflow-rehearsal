AI Fabric · Placement × Electrical Responsibility

第一个结果不是“谁赢”，而是什么条件会改变前沿

本卷宗把同一 AI fabric 服务目标作为共同分母，先比较光学放在哪里，再比较信号恢复责任放在哪里。当前证据可以画出决策边界和反转条件，但还不能生成可信的系统总分、精确阈值或市场胜负。

第一次看到这些词？先读 Front-panel、NPO、CPO 位置图 和 Pareto 白话词典，再回来读条件卡。
当前裁决：四种组合都有条件进入 Pareto 前沿，没有无条件冠军。

前面板方案的核心价值是独立接口与模块边界；LPO 用 Host 与系统验证责任换取模块侧功耗空间；NPO 用板级集成责任换取更短的潜在电路径；CPO 把光引擎带到 ASIC 同一 first-level substrate，同时把封装、热、光纤、光源和维修升级为系统问题。

先冻结共同分母：不满足这些条件，不允许排总名次

服务目标相同 endpoint、流量、bisection bandwidth、oversubscription
网络边界相同 hop/latency、availability、部署范围和证据日期
器件边界相同代际、lane rate、FEC/BER 与 reach 分布
核算边界同时计入 optics、Host/board、cooling、failure domain 与 service
本版分析模式：qualitative_boundary_map_no_numeric_system_model。topology、radix、Host 增量功耗、cooling、failure rate、MTTR 与 yield 仍未闭合，因此只报告硬门和 Pareto 候选，不制造统一分数。

当前进入前沿的四张条件卡

FP-R
front panel × retimed

独立边界优先

进入前沿：独立模块更换、多供应商电边界或故障隔离是硬约束，并且面板、电通道与散热仍能闭合。

负担位置：模块承担更多信号恢复、功耗、热和局部诊断。

退出条件：面板热密度或高速电通道成为 active constraint。

FP-L
front panel × linear

Host 闭合优先

进入前沿：Host 与模块能在目标 FEC、温度、老化和多供应商矩阵下闭合 linear channel，且系统分项测量没有抵消模块侧收益。

负担位置：均衡、校准、互操作、遥测与故障定位更多进入 Host 和系统验证。

退出条件：Host/board 不能稳定闭合，或系统净功耗没有改善。

NPO
near package × object-specific electrical

电路径与面板密度优先

进入前沿：ASIC 到前面板的电路径或面板密度成为硬约束，同时具名实现的板级光纤、冷却、attach/rework 与 service workflow 可接受。

负担位置：attach、冷板、板级光纤、校准和维修进入主板与系统集成。

退出条件：attach 的热/信号/返工代价或服务边界抵消路径收益。

CPO
same substrate × object-specific electrical

Package I/O 与最高密度优先

进入前沿：package I/O escape、电路径或系统密度成为前面板/NPO 无法解决的硬约束，并且系统能接住 package thermal、fiber、laser 与 service ownership。

负担位置：封装、热、内部光纤、光源、failure domain 与服务边界成为系统问题。

退出条件：package 故障域、冷却、engine service、成熟度或良率代价过高。

五种会让排序反转的 active constraint

反转约束从什么变成硬门当前条件化结果不能偷换成什么
R01 · 服务边界独立更换、多供应商边界、故障隔离与可执行维修流程满足具名服务合同的 front-panel 方案保持前沿；NPO/CPO 必须证明实际 replaceable unit不能写成“所有可插拔都易修”或“所有 CPO 都不可修”
R02 · 模块/面板功耗Host 已证明 linear closure，系统分项功耗也未抵消模块收益FP-LPO 可替代 FP-Retimed 进入前沿不能用模块 nameplate 上限直接宣布系统节能
R03 · 电通道余量lane rate、连接器、走线、串扰或面板密度使 front-panel 无法闭合NPO 相对价值提高并进入前沿不能由 NPO 标签自动补成 linear、socket 或 field-replaceable
R04 · Package I/Onear-package 路径或板级扇出仍不能满足硬约束，且 CPO 系统责任已闭合CPO 进入或取代 NPO 的前沿位置不能写成“到某个速率就必然 CPO”
R05 · 生命周期failure domain、MTTR、RMA、yield 与 cooling 成本进入同一边界排序可能再次反转；当前资料不足以判定方向不能用单项电损耗或模块功耗代替 TCO

这一版真正产出的结论

现在可以用于决策

可以先判断是哪一项硬约束在起作用，再决定 placement；可以拒绝 LPO vs CPO 的错层比较；可以说明每条路线把哪些责任迁给模块、Host、主板、封装或服务体系；可以列出使前沿发生反转的验证条件。

现在仍不能下结论

不能给 front-panel、NPO、CPO 的统一总排名；不能给系统节能比例、精确 lane-rate 切换点、MTTR、良率或 TCO；也不能由某个 exact-object 的 attach、光源或维修流程外推整个路线。

下一次真正的定量版本需要：冻结一个可复现 AI fabric 的 topology、radix、port/reach 和 availability 目标，同步取得 optics、Host/board、PSU、cooling、BER/FEC、failure unit 与 service workflow 数据。无权重先画 Pareto frontier；权重与硬约束必须在模型输出可见前冻结。
