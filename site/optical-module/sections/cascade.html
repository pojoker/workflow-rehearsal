WHY 串联同一约束可以带出不同、甚至相反的工程选择
从约束走到路线

技术路线不是“突然出现”，而是对约束传导方式的不同回答

最容易缺失的就是中间这几步：需求不是直接指向 EML、SiPh、LPO 或 CPO；它先改变约束，再改变某种方案的相对价值。每条链还必须继续追踪代价去了哪里。

链 1电通道余量变小
上游变化200G/lane、较长 C2M 路径
→
约束损耗、反射、串扰占用余量
→
两个方向增加 retiming或缩短路径 / linear
→
下游代价模块功耗增加，或 Host/封装/验证责任增加
因此 Retimed 与 LPO 并不是简单的新旧关系，而是对“在哪里恢复信号、由谁承担风险”的不同回答。
链 2面板与纤芯密度受限
上游变化端口吞吐和 lane 数增加
→
约束连接器、光纤、极性与布线膨胀
→
两个方向Parallel：保留空间 lane或WDM：按波长复用
→
下游代价多纤管理，或 mux/demux、波长与温控责任
因此“纤芯更少”不等于 BOM 更少：空间管理责任可能转化为光谱管理责任。
链 3功耗与热密度受限
上游变化更高速 DSP、光源与更多密集端口
→
约束模块壳温、风道与面板功率密度
→
多个方向先进制程 / LPO / 更强散热或NPO / CPO 改变放置
→
下游代价Host 分责、共同封装、外置光源、维修边界重画
因此 CPO 的吸引力来自系统级边界变化，不等于“只要到 3.2T 就必然采用 CPO”。

提速时必须同时看三个分母

每只模块W / module · $ / module

1.6T 模块的绝对功耗或售价可能高于 800G；这反映单只产品压力。

每单位带宽W / Tb/s · $ / Gb/s

绝对功耗上升时，每比特能耗仍可能下降；这是效率口径。

整个系统ASIC + optics + cooling + service

模块省下的功耗、成本或复杂度可能转移到 Host、交换芯片、冷却、封装、测试和维护。

不能跨分母下结论：“模块功耗更低”“每比特更高效”和“交换机系统更省电”是三个不同命题；同样，“零件减少”“BOM 降低”和“全生命周期成本降低”也不是同一句话。
观察到的压力可以继续问还不能直接推出
200G/lane 电通道更难Retimed、LRO、LPO 分别把均衡、FEC、观测和故障责任放在哪里？不能说 LPO 必然更省系统功耗，也不能说 DSP 一定不可缺
光 lane 带宽提高Driver、modulator、PD、TIA、封装寄生和目标 reach 如何共同闭合？不能只凭 1.6T 标签判断必须使用 EML 或 SiPh
纤芯与面板密度提高Parallel 与 WDM 分别增加哪些接口、温控、耦合和维护责任？不能只按光纤数量判断成本和可靠性
模块和面板热密度提高模块、ASIC、风扇/液冷和外置激光器的功耗分别是多少？不能用两款模块 nameplate 功耗代替系统受控比较
装配与测试边界收紧KGD、耦合、老化、温箱、端到端 BER 和返工流程怎样变化？不能自动推出设备价值量、测试时长或良率方向
延伸阅读：Broadcom Tomahawk 6提供 102.4Tb/s 交换容量与 100G/200G 接口对象；IEEE P802.3dj给出 200G 至 1.6T Ethernet 的标准工作边界；OIF 224G 接口框架把问题展开到芯片、封装、连接器、信道与系统。
