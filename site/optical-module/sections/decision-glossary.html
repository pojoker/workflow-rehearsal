Pareto 是什么？它不是“最佳方案”的高级说法

现实方案经常同时比较功耗、成本、性能、可靠性和维修。如果一个方案在所有重要维度上都不比另一个更好，它就可以被淘汰；剩下那些各有优势、无法被另一个方案全面压过的选择，构成 Pareto 前沿。

方案 A：功耗低，但维修复杂在功耗上赢，在维修上输
无法全面压过
方案 B：功耗高一点，但容易更换在维修上赢，在功耗上输
A 和 B 都可能在 Pareto 前沿。

这不表示两者一样好，只表示在没有权重和硬约束时，不能诚实地把其中一个全面淘汰。如果用户后来规定“维修时间必须少于某个上限”，这个硬约束才可能把 A 排除。

卷宗里的高频词，翻译成白话

术语白话意思在这个项目里怎么用最容易误解成什么
Pareto frontier
帕累托前沿		没有被另一个方案在所有重要维度上全面压过的候选集合没有预先权重时，只说哪些方案仍值得选，不硬排第一名不是“最先进路线”，也不是“市场份额最高”
Active constraint
起作用的硬约束		真正卡住系统、让某个方案不可行或排序改变的那条限制可能是电通道、面板功耗、散热、维修时间或封装 I/O不是所有困难的罗列；必须指出哪一项正在决定结果
Host / Host ASIC光模块所连接的主机系统或交换芯片一侧研究信号恢复、FEC、均衡和管理责任到底由模块还是主机承担不是最终客户，也不是服务器整机的泛称
SerDes把芯片内部并行数据变成高速串行电信号、并在另一端恢复的电路决定 Host 能否接住更长、更复杂或更线性的高速链路“更强 SerDes”不是一个单独 dB 数字，也不保证 LPO 一定可行
Retimed模块里有电路把受损高速信号重新判定、整形并重新定时模块承担更多恢复责任，Host 与模块之间的边界通常更清楚不自动证明具体 DSP、ADC、DAC 或 FEC 的内部实现
Linear / LPO减少模块内完整重定时，让更多端到端信号恢复责任回到 Host可能降低模块侧功耗，但增加 Host、通道、校准和互操作要求不是“没有任何芯片”，也不是系统总功耗必然更低
First-level substrateHost ASIC 所在封装的第一层承载基板本项目用它区分 CPO 的同一级封装关系不等于 ASIC 与光引擎做成同一颗芯片
Failure domain
故障域		一个部件坏掉时，会被一起影响、一起停机或一起更换的范围比较“坏一只模块”“坏一个光引擎”“坏一块板或整包”的影响差异不是单个器件的故障率；范围与概率是两件事
MTTR从故障发生到恢复服务通常需要多长时间需要同时记录谁修、在哪里修、用什么工具、是否断电以及修后测试socket、可插拔或热插拔标签本身都不能给出 MTTR
TCO从购买、供电、冷却、维护到报废的全生命周期总成本避免只看模块价格或单项功耗就宣布哪条路线更便宜不是 BOM 成本，也不是一次采购价
UNKNOWN当前证据不足，主动保留空白告诉后续研究需要什么数据才能继续，而不是用行业印象补答案不是“没有价值”，也不是“否定结论”

读决策卷宗时，只要连续问四句话

1

目标相同吗？

速率、距离、网络服务、温度、可用性和证据日期是否使用同一分母。

2

谁承担责任？

模块、Host、主板、封装、冷却和维修体系分别多了什么、少了什么。

3

真正卡住哪一项？

找 active constraint，而不是把所有优缺点平均成一个看似客观的分数。

4

什么证据会改判？

要求阈值、反例、受控测量或可执行维修流程；缺少就明确 UNKNOWN。

最短记法：Pareto 前沿 = 目前还不能被全面淘汰的方案；active constraint = 真正让排序改变的硬门；UNKNOWN = 缺证据，不是假装确定。
