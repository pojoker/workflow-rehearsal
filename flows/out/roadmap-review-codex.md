# ROADMAP v1.5 草案评审（Codex）

评审对象：`flows/ROADMAP-v1.5-draft.md`  
评审日期：2026-07-23  
结论性质：红队评审，不修改路线草案及其他项目资产

## 总体判断

路线方向大体正确，但当前排序把一次尚不能归因于“图谱方法”的事后回测试跑放得过高，
同时漏掉了更紧迫的活资产一致性修复；R2 可构造 Lumentum 侧采购分母的保守上界，但
仅凭现有 Lumentum/Fabrinet 年报仍缺客户级会计归类的最后一桥，不能预设 E038 可回 A。

建议不是简单交换 R1/R2，而是先补一个 **R0：红队裁决执行完整性与活资产一致性审计**，
再按“R2 边等级闭合审查 → R3 关系时间轴 → R4 高价值对手方核对 → R6 报告修复 →
R1 协议修复及试跑 → R5 触发式采集 → R7 触发式监测”的顺序执行。SOP 修订应最后做，
只吸收真正跑过且有日志的部分。

## 一、对草案末尾四个问题的直接回答

### 1. R1 放首位确实高估了单次回测的信息量

不只是“单样本不能下结论”，而是现协议还不能产生草案所称的“图谱是否有预测力”的
可归因数据点：

1. `backtest-protocol-v1.md:181-187` 把 T0 写为 2025-06-20，但同时声明 2025-05
   海关批次的实际公开日尚未核验，核验失败则必须推迟 T0。因此六要素尚未真正冻结，
   草案 `ROADMAP:8` 的“已冻结”越过证据。
2. 协议定义了预测方向和阈值，却没有定义“图谱方法”如何从 T0 信息集生成
   2025-07～12 六个月的数值预测。`backtest-protocol-v1.md:222-226` 又要求计算
   “预测方法”的 MAE；没有六个逐月预测值，MAE 无从计算。
3. 候选 A 使用的是同一条美马出口差额序列在交叉发生后的延续性，最多检验某个
   趋势规则；协议没有指出哪一项关系图谱信号进入预测、如何形成相对朴素持平和线性
   外推的增量判断。成功也不能归因于“图谱有预测力”。
4. 试点和判据是在 2026-07、已知 2025H2 实际结果后选定。文件隔离可防止执行时直接
   偷看，但不能消除事后选题、阈值和事件选择偏差。它适合作为**回测工作流彩排**，
   不是干净的样本外验证。

因此 R1 应改为两个门：

- **R1a [修复]**：核官方发布日期，冻结 T0；预先写死图谱信号、预测函数、六个月预测
  向量、缺失值处理和基准计算；由未参与选题者在揭盲前审协议。
- **R1b [验证]**：跑一次，并把结果限定为“协议/执行流程是否可运行”的样本；不得称为
  “图谱预测力的第一个可证伪数据点”。若要检验图谱增量价值，应再预注册一个真正未来
  窗口，或至少建立多个不按结果挑选的历史事件样本。

### 2. R2：Lumentum 侧上界可构造，但现有材料不能单独闭合排他

我复核了本地 `lite_fy2023_body.txt`。FY2023 10-K 至少提供：

- FY2023 net revenue 约 17.670 亿美元；
- cost of sales 约占 63.0%，即约 11.132 亿美元；
- 期末/期初存货 4.086/2.501 亿美元，净增加 1.585 亿美元；
- NeoPhotonics 并购带入存货 0.843 亿美元；
- 存货公允价值 step-up 0.178 亿美元且 FY2023 已摊完；
- 另有存货过剩/陈旧相关费用及并购影响的披露。

不扣并购带入存货、不剔除人工制造费用和其他非采购成本，直接用
`cost of sales + 期末存货 - 期初存货`，即可得到约 **12.717 亿美元**的故意偏高上界。
即使把约 0.848 亿美元的 acquired-developed-intangibles amortization 也错误地一并
塞入以进一步放宽，上界约 **13.565 亿美元**。两种口径的 10% 仅约 1.27～1.36 亿美元，
都远低于 Fabrinet 对 Lumentum 的约 4.07 亿美元收入。

这说明：

- **分母侧的量级排除可以显著加强**；Lumentum 的 net inventory purchases 不可能合理
  接近原论证所需的 40.7 亿美元。
- 但严格闭合仍需要证明 Fabrinet 的 4.07 亿美元中，至少约 **30%～32%** 进入 Lumentum
  所称的 `net inventory purchases`。Fabrinet 10-K 只在公司整体层面称收入主要来自产品
  组装、定制光学及相关制造，并未披露 Lumentum 这一客户的收入构成、客户供料、净额/
  总额列报或 Lumentum 端具体记账科目。
- 公司整体业务模式和双方财年重合，是很强的一致性证据，却不是客户级会计归类的硬桥。
  合理替代解释仍包括：部分收入为制造服务、工具/NRE、客户供料下的加工费，或在
  Lumentum 端不进入该 `net inventory purchases` 分母。

所以，R2 不应写成“算出上界，能闭合则回 A”。正确准入条件应是：

> 同一财年、同一合并主体下，先给出 Lumentum 净存货采购的保守上界 U；再以客户合同、
> 客户级收入说明或 Lumentum 会计披露证明 Fabrinet 收入中进入该分母的最低金额 L；
> 只有 `L > 10% × U`，且 Lumentum 同口径披露“仅一家 ≥10%”，才形成严格排他。

现有本地材料足以完成 U，不足以给出可审计的 L。**本轮大概率结论应是“B 级终态，
置信度增强但不升级”**；并非理论上永远注定 B，但若没有客户级会计归类新证据，不应
靠一般业务描述回 A。

### 3. “依据”栏并非全部站得住

- R1 的“协议已冻结六要素”不成立：T0 尚待官方发布日期核验，预测方法/预测向量也未
  定义。
- R2 对 RT-006 的引用基本准确，但把“上界+会计归类”压缩成一个可能轻易完成的本地
  提取动作，低估了客户级归类证据缺口。
- R3 的 per-edge 限制确实存在；但“censored 逻辑不变”站不住。某一 edge 在某年
  censored，另一 edge 同年仍可 observed；聚合到关系级时必须设状态优先规则，不能把
  edge 级截尾原样搬过去。
- R4 的“仅 3 条双侧有披露渠道”与
  `counterparty-audit-candidates.csv` 不符。该表 15 条的 B 方列均写“是”；准确说法是
  **前三条被列为高优先级**，而不是只有三条有渠道。且 P01 明示“预期不可见”，不能与
  P02/P03 的双侧可比性混写。
- R5 的数据缺口与 `VERIFICATION-v1.3.md` 基本一致；但 2026-07 出口月度属于未来发布
  触发项，“通道定型”只证明抓取工艺可复用，不证明数据已经可取。
- R6 的 81/42→99/48 报告债务成立；但 `VERSION-STATE.md:21,28-29,43-44` 把下一份报告
  称为 v1.4，草案改称 v1.5，需先区分“路线版本”和“报告版本”。“全部来自 v1.4 实测”
  也不成立：回测协议只设计未运行，关系级时间聚合尚未做，“每版必跑 codex 红队”是
  新治理规则而非多版实测结论。
- R7 没有“依据”栏；而“等待触发、不主动投入”与“ggzy 月度看一眼”互相冲突，后者
  本身就是主动、重复的监测成本。

### 4. 遗漏了两个边际价值高于现有 R1/R5/R7 的事项

#### O1 [修复，最高优先] 红队裁决执行完整性与活资产一致性

`redteam-disposition-v1.4.md:4-5` 声称活文件已按 24 条发现全盘执行，但当前仍有：

- `output/deanonymization-cases.md:93-101` 标 B，`135-136` 又判 A；
- `output/edges.csv:E038` 等级为 B，验证状态仍写“判例#004-A级”，备注仍称“排他性
  论证”；
- `flows/src/build_atlas_v14.py:461` 及已生成 v1.4 HTML 仍称“3 条推断边……判定 A级”；
- `SOP.md:163` 仍把判例 #004 写成已验证 A 级路径。

这些都是当前活资产，不是 `VERSION-STATE` 中允许只登记勘误的冻结旧报告。读者从不同
入口会得到互斥等级，直接损害图谱可信度。应在任何新验证、报告重写和 SOP 修订前完成
一次“裁决记录 → 活资产”逐条对账，并设发布门：同一 edge 的等级、判例结论、图谱摘要、
SOP 示例必须一致。

#### O2 [修复，高优先] 建立关系级聚合前的数据契约

R3 不能只在脚本中按 `(供方文本, 需方文本)` groupby。E038 使用
`Fabrinet(解匿)`，E005/E068 使用 `Fabrinet`，原样聚合会把同一关系拆开。至少需先定义：

- 用节点 ID/别名表而不是显示名作关系键；
- 同一关系同一年多 edge 的去重与冲突规则；
- FY 与自然年的时间键，不把“2023”强行视为同一期间；
- `observed` 与 `censored` 同年冲突时的关系级状态优先级；
- 保留每个聚合事件的来源 edge IDs，不能为得到连续线而丢失证据链。

这份契约的边际价值高于直接改脚本，因为它防止关系视图制造新的伪连续性。

## 二、R1—R7 逐项评审

### R1 [验证] 回测试点

**裁决：降序，先修后跑；类型改为 `[修复→验证]`。**

“单次不构成结论”的自限是对的，但价值主张仍越级。把产出目标改为：
“验证协议能否无前视地执行，并暴露数据/判据摩擦”；只有预定义图谱信号和数值预测函数
后，才可谈方法的一个样本。R1 不应阻塞当前图谱等级、时间轴和报告修复。

### R2 [修复] 判例 #004

**裁决：保留高优先，但改名为“B 级终态审查/有条件回升”，不得预设 A。**

优点是零新采集、直接触及唯一一条 B 级推断边。应先写闭合不等式和准入标准，再计算；
结果分三类：

1. U 与客户级 L 均闭合，且 `L > 0.1U`：可申请回 A；
2. 只有 U、没有 L：维持 B，补强量级说明；
3. 连 U 也因口径缺失无法审计：维持 B，并停止继续加工。

还应同时清理判例库内部 A/B 自相矛盾；否则“R2 结论”没有唯一落点。

### R3 [修复] 关系级时间聚合

**裁决：保留高优先，排在 R2 后；先定契约再实现。**

需求依据成立，且对所有多年关系有系统价值。动作中的“censored 逻辑不变”须删除。
关系级状态要从 edge 事件重新裁决，不是简单重算 first/last。另，“五态时间模型”措辞
不严谨：代码枚举包含 `first_observed / observed / last_observed /
confirmed_started / confirmed_ended / censored` 六种；当前只有五种非零，不等于模型
只有五态。

### R4 [验证] 对手方审计

**裁决：保留，但依据改写，排在 R3 后。**

应写成“执行 Y5 前三条高优先候选，其中 P02 并入 R2，本轮跑 P01/P03”。结果分类建议
改为：

- 双侧同主体、同期间、同金额/科目吻合；
- 仅量级/地域不矛盾（弱一致性，不升级关系等级）；
- 口径不可比；
- 制度性不可见；
- 出现实质矛盾，需进一步核查。

“正向吻合”不能覆盖天孚-Fabrinet 的一般规模/地域相容；Fabrinet 不实名供应商时，
未冲突不等于双侧确认。光迅-烽火若找到关联交易镜像，则应逐项核合并范围、采购/销售
方向、含税口径与 2023 同期金额。

### R5 [采集] 海关更新

**裁决：保留为触发式批处理，当前不抢占修复序列。**

补年能提高时间覆盖，但不会直接修复企业归因。验收表述必须继续限定为“国别/贸易方式
申报结构”，不得把 85414900 等宽税号重新写成光芯片依赖、技术来源或 Fabrinet 企业
流向。出口 2026-07 及以后按官方完整月发布触发，不为追求“最新”采未完月。

### R6 [修复] 报告与 SOP 收敛

**裁决：拆成 R6a 报告和 R6b SOP；报告中高优先，SOP 最后。**

- R6a 应在 R0、R2、R3、R4 完成后，按明确快照重写当前报告；先裁定报告名是 v1.4
  还是 v1.5。判例分布应写清范围：“已完成身份解匿判例 #002/#003/#004 为 2A+1B；
  #006 仅 C 级候选，#001/#005 未成判例”。
- R6b 只能吸收有执行日志的机制。一轮独立红队证明该门有价值，但不能推出“每版必跑
  Codex”；宜写成角色和触发条件，例如“承重结论或等级变化的发布版必须经过独立对抗
  复核并留裁决记录”。回测协议应先标“设计已完成、运行未验证”，关系级模型在 R3
  跑通前也不得进入正式 SOP。

### R7 [探索] 监测位

**裁决：保留在路线末尾，但改为真正的事件触发，不做固定月巡。**

- 集团一：仅在联讯新增问询回复/注册稿披露客户身份或可比金额时触发；
- 设备池：先定义“同主体、同指标、同频率至少多少期”再称“凑齐”，否则没有停机线；
- ggzy：已知目标批次零命中，固定月巡边际价值低。只在运营商发布新批次、镜像收录规则
  改变或出现可定位项目号时触发。

## 三、标签与措辞审计

草案首页称“每项标注了类型与价值主张”，实际只有 R1 明示
“价值主张（推断，未证）”；R2—R7 均缺价值主张标签。应逐项补：

| 项 | 建议类型 | 价值主张证据状态 |
|---|---|---|
| R0（新增） | 修复 | 已证：当前活资产存在互斥等级 |
| R1 | 修复→验证 | 未证：只先验证流程可运行性 |
| R2 | 修复/验证 | 部分已证：分母上界可算；最终升级未证 |
| R3 | 修复 | 已证：per-edge 造成关系连续性断裂；实现正确性未证 |
| R4 | 验证 | 未证：双侧核对的新增信息量待跑 |
| R5 | 采集 | 已证数据缺口；研究增量价值未证 |
| R6a | 修复 | 已证：报告落后且活资产措辞漂移 |
| R6b | 修复 | 部分已证：独立红队有效；“每版必跑”未证 |
| R7 | 探索/监测 | 未证，必须事件触发 |

需降级或纠正的具体措辞：

- “六要素已冻结” → “六要素框架已写，T0 发布日与预测函数仍待闭合”；
- “图谱是否有预测力的第一个可证伪数据点” → “回测执行流程的首个试跑样本”；
- “能闭合则 E038 回 A” → 补 `L > 0.1U` 及客户级归类条件；
- “仅 3 条双侧有披露渠道” → “Y5 前三条高优先候选”；
- “censored 逻辑不变” → “关系级冲突规则另行定义”；
- “全部来自 v1.4 实测” → 分开写“已运行/仅设计/待运行”；
- “五态时间模型” → “六枚举状态（当前五种非零）”；
- “不主动投入”与“月度看一眼”二选一，不能并存。

## 四、最终推荐执行序

1. **R0（新增）**：逐条核对 24 条红队裁决是否落实到所有活资产；先统一 E038、判例库、
   图谱摘要、SOP 示例和版本命名。
2. **R2**：按 `U/L` 双门做判例 #004 终态审查；当前预期是补强 B，而非回 A。
3. **R3**：先定关系级键、期间与状态冲突契约，再产出 relationship timeline。
4. **R4**：跑 P01/P03；严格区分双侧确认、弱一致、不可比与不可见。
5. **R6a**：以完成上述修复后的唯一快照重写当前研究报告。
6. **R1a → R1b**：修协议后做一次回测工作流试跑；不将结果宣传为图谱预测力。
7. **R5**：官方完整月/补年数据到位后一次性采集并按既有边界入库。
8. **R7**：仅事件触发监测，不做无差别月巡。
9. **R6b**：最后从 R0—R7 的实际日志修 SOP；未运行的机制留在“待验证路径”，不写成
   正式步骤。

一句话执行序：**先修活资产真相，再闭合边与时间关系，随后更新报告；回测试跑靠后，
采集与监测按触发执行，SOP 最后从执行记录中生长。**
