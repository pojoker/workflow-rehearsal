# discovery-queue README — 统一发现队列 + 判定闸（**原型-未准入**）

- 代码：`flows/src/discovery_queue.py`（kimi/k3 车道；D2 硬化版）
- 定位：ROADMAP-v1.7a（已冻结）"常设容器 = 统一发现队列 + 判定闸"的**候选实现**。
- 状态：**原型-未准入**。保持该标注直至终验做硬化评审并决定转正；转正前其产出
  不得作为任何边的证据或 D 项分母引用。

## 1. 架构位置（v1.7a）

容器常设、算子触发：常设的是**队列 + 判定闸**（本容器）；算子按事件/缺口/治理
触发，**无触发不扫描**，不为流程完整制造任务。容器职责只有三件：

1. 把各发现算子的产出归一到一个队列 schema；
2. 用状态机驱动 `待闸 → 过闸-待边工序 / 剔除-已登记 → 已入图`；
3. 承载判定闸台账（schema 已落地），为 D 项候选集覆盖率提供**只认过闸项**的分母。

容器**不作任何闸裁决**——判定归终验（闸 owner=终验），本车道只交空骨架台账。

## 3. 队列 schema（proto-discovery-queue.csv）

| 字段 | 说明 |
|---|---|
| `queue_id` | 全局唯一（A3）；建议 `DQ-<算子标记>-<序号>` |
| `发现算子` | ∈ {media_lead, customs_diff, bom_scan, bfs_jump, gap_list}（A1） |
| `对象类型` | company / flow_anomaly 等 |
| `对象` | 候选主体或异常对象（容器不做实体裁决） |
| `发现证据(URL/出处)` | 必须可回溯：URL 或文件名+口径 |
| `发现日期` | 报道/数据/检索日期 |
| `待验证T1路径` | 下一步核到一手披露的路径 |
| `状态` | ∈ {待闸， 过闸-待边工序， 剔除-已登记， 已入图}（A2） |
| `闸裁决` `闸裁决人` `闸裁决时间戳` `裁决理由` | 入队时全空；由终验裁决后回填（队列内是台账的冗余视图） |
| `备注` | bom_scan 行必须在此带"词表出处（含版本）"（A4） |

## 4. 判定闸台账 schema（proto-gate-ledger-skeleton.csv，v1.7a 落地）

字段：`gate_id, queue_id, 对象, 命中上下文(段落/词), 段落类型预判, 闸裁决, 裁决人, 裁决时间戳, 理由, 剔除登记号(若剔除)`

**六类裁决**（`闸裁决` 唯一合法值集）：

| 裁决 | 含义 |
|---|---|
| 生产中 | 对象现实在生产该部件/产品 |
| 拟生产 | 在建/募投/送样等明确指向生产、尚未量产 |
| 采购使用 | 对象是采购/使用方，不是生产方 |
| 销售代理 | 对象是经销/代理通道，不是生产方 |
| 仅提及 | 段落仅提及，无生产或交易语义 |
| 无法判断 | 证据不足，如实登记不硬判 |

**裁决四件套不变式**：`闸裁决 / 裁决人 / 裁决时间戳 / 理由` 同空（未裁决）或
同填（已裁决），不允许半填；时间戳为 ISO 8601。裁决逐条入台账留痕，
`queue_id` 必须存在于队列（A5）。台账写入权在终验；本脚本产出保持空骨架，
自检中的正/反例只存在于内存，不落盘。

## 5. 发现算子与触发条件

| 算子 | 触发条件（v1.7a） | 状态 | 输入 |
|---|---|---|---|
| media_lead | 媒体事件线索入池 | 真实 | `flows/out/leads-pool.csv` |

| gap_list（S0c 必要接口/结构缺口清单） | 缺口触发 | 算子 id 保留，接口预留未注册 | ——（非边：BOM 必需部件不能推出交易边） |

## 6. 真实算子接入（替换 MOCK）

接口为 `DiscoveryOperator`（见源码 docstring）。步骤：

1. 子类化，填 `name`（∈ 已知算子集）/ `trigger` / `object_type`，实现 `scan()`；
2. `scan()` 只经 `new_row()` 产出行：状态=待闸、四个闸字段留空（裁决归终验）；
   证据字段必须可回溯（URL/出处+日期）；
3. 注册进 `OPERATOR_REGISTRY` —— 队列 schema、闸台账、A1-A6 自检均无需改动。

MOCK 算子（`is_mock=True`）仅演示接口与 schema，产出**不得引用**。

## 7. 候选集覆盖率（D 项；禁称总体查全）

按 v1.7a 确认审最小条款 2：

- `C_layer` = 冻结语料与词表下 S0a 命中并完成判定闸裁决的**生产候选**集合；
- `G_layer` = 已取得合格证据并进入对应图层的主体集合；
- 候选集覆盖率 = `|G_layer ∩ C_layer| / |C_layer|`；
- 另报候选处理率 = `已裁决 / (已裁决 + 待裁决)`——待裁决不得从分母消失，
  须报数量与老化时间。

分母冻结三硬条件：词表版本锁定 / 闸裁决完成 / 集合快照落盘。
**A6 防线**：分母只统计"过闸且裁决=生产中"的对象，原始命中永远不作分母；
拟生产是否计入 `C_layer` 属终验口径，本脚本不预断。
`proto-coverage-mock.csv` 仅为该公式的 MOCK 演示行。

## 8. 纪律断言（自检，失败即退出码 1）

- A1 发现算子 ∈ 已知集合；A2 状态 ∈ 状态机合法值；A2b 队列内闸裁决 ∈ 六类；
- A3 `queue_id` 唯一；A4 bom_scan 行必须带词表出处（含版本）；
- A5 闸台账逐行：`queue_id` 存在、裁决 ∈ 六类、四件套同空或同填、时间戳 ISO
  （含 MOCK 正例必过 / 四类反例必拦的内存自测）；
- A6 覆盖率分母只认"过闸且裁决=生产中"（见 §7）。
